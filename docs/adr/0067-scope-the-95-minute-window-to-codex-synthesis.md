# 将 95 分钟窗口限定为 Codex synthesis 重试窗口

Knowledge v1 的 95-minute attempt window 只拥有 Codex synthesis 的运行与重试序列：它从第一个 Codex 子进程成功启动开始，跨越实际 attempt 的进程运行、终止、provider 捕获、分类和两段 retry backoff，到运行序列确定结束为止；Answer validation 与 rendering 不在该窗口内。Deadline 在活跃 attempt 尚未完成捕获与分类时触发，该真实 item 锁存 timeout terminal signal 并立即停止已有进程树；安全收尾仍必须完成，但不能借此继续模型执行或启动重试。该 signal 在 [ADR 0068](./0068-arbitrate-attempt-terminal-signals-in-two-stages.md) 的生命周期完整性门禁通过后成为 final `timeout`，若启动、退出状态、进程树或捕获收尾自身失败则由最高优先级 `process_error` 覆盖。Deadline 在 backoff 或下一次 launch commitment 前触发时，不创建占位 attempt，也不向历史 item 注入虚构 `timeout`；如果用户取消也在该阶段到达，就比较取消 observation 与固定 window deadline，取消早于或等于 deadline 时顶层 `interrupted` 胜出，否则只由已经实际存在的 transient `failure_class` 集合决定耗尽终因，同类使用对应耗尽 code，多类使用 `codex_transient_exhausted`。Codex 进程/provider 捕获正常结束后先关闭该运行窗口，再进入 validation，因此后来发生的输出无效只能是 `answer_output_invalid`，不能改写 attempt 或伪装成 synthesis timeout。该选择以 95 分钟不约束确定性验证和渲染为代价，保持真实 attempt、阶段所有权和 terminal manifest 可以互相推导。

ADR 0079 冻结 capture overflow 也会请求停止同一 attempt Job，并要求 stdout mechanical drain 到 EOF；该 drain 只是安全收尾，不是继续模型执行、等待语义输出或延长 deadline。若 overflow 与 timeout 同时或先后被观察，两项事实都保留并可合并为一次 stop request；capture-finalization boundary 通过后，ADR 0080 的 overflow `process_error` 不比较两者先后并覆盖 timeout，立即关闭 attempt window 且禁止 retry。安全边界无法证明时只留 staging，不能伪造 timeout 或 process terminal manifest。
