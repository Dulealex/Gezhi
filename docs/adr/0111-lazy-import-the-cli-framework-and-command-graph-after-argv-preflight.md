# 只在 argv preflight 通过后导入 CLI framework 与 command graph

未来任何由本项目提供的公开 one-shot `gezhi` CLI 都必须使用强入口边界：最小 project bootstrap 先运行 [ADR 0110](./0110-run-a-decoded-argv-resource-preflight-before-typer.md) 的 `RawArgvPreflightV1`，只有该 seam 通过后，才 lazy-import Typer 0.27.0、Rich、CLI app factory、完整 command/subcommand graph，以及 Literature、Knowledge 和未来 Bot 的 command adapters。Help、version、known/unknown command 与字面 `--json` 都不例外；它们需要 Typer 处理，因此也必须先经过 preflight。项目不得在 bootstrap module、package `__init__`、preflight module 或其 project-owned transitive import closure 中直接或间接预载这些后置模块，也不得为注册 decorator、类型注解、默认值或 help metadata 提前构造 command graph。ADR 0113 已冻结 Gezhi Windows V1 不提供 shell completion：PASS 后构造的 root graph 不注册 completion options，并以 project-owned no-op 阻断 Typer completion environment path；completion 因而不是本 ADR 的例外或第二套输入。ADR 0112 已建立 packaged project、console-script metadata 与 inert package root；在实际 bootstrap/preflight module 完成前，生成的 executable 仍不宣称通过本 ADR 的 runtime contract smoke。

Preflight 尚未通过、[ADR 0115](./0115-cap-raw-argv-at-128-arguments-8192-elements-each-and-16384-total.md) 的权威 resource violation 或 preflight 自身异常时，项目不得尝试 import、预热、缓存或 fallback 构造 Typer/Rich/command graph，也不得调用 command/app factory。Resource violation 只由 [ADR 0116](./0116-return-2-with-one-fixed-stderr-line-for-raw-argv-resource-violation.md) 的最小 bootstrap presenter 写 fixed stderr 并返回 `2`；preflight 自身异常仍保持独立 internal boundary。Preflight 通过后的 lazy import 或 command-graph construction failure 是另一种 bootstrap/import failure，不得倒推成 argv resource violation、parser argument failure、Knowledge `blocked/failed/interrupted`、`CliDiagnosticItemV1` 或 ADR 0108 presentation failure；其文案、channel 与 exit 仍由后续 bootstrap contract 冻结。

“强入口”只约束 project-owned import ordering，不声称进程此前没有 I/O、allocation 或输出。Windows launcher/`CreateProcessW`、CPython 初始化与 `sys.argv` materialization、`site`/`.pth`/外部 `sitecustomize`、entry stub，以及读取最小 bootstrap/preflight module 自身 source/bytecode 都发生在门禁之前；这些 failure 不由本 ADR 接管。受支持的 fresh one-shot launch 必须能证明：Typer、Rich 或 command modules 若在进入 project bootstrap 时尚未被外部预载，则项目 import closure 在 preflight observation point 及任何非 PASS path 都不会加载它们。项目不枚举、清除或回滚外部或 PASS 后 partial import 已经放入 `sys.modules` 的 module；embedded/reentrant host 与外部预加载不在此 negative-set 保证内。

实现必须保持一个薄的 bootstrap import closure：package `__init__`、bootstrap、preflight module 及其 project-owned transitive imports 在 PASS 前不得直接或间接加载 Typer、Rich、CLI app factory 或完整 command graph，也不得提前构造 command graph。[ADR 0112](./0112-package-gezhi-with-two-launch-adapters-and-one-bootstrap-seam.md) 已进一步冻结 `src/gezhi/` packaged layout、console script 与 `python -m gezhi` 两个 launcher adapter，以及二者共同指向 `gezhi.bootstrap:main` 的唯一 seam；本 ADR 仍不冻结逐 module allowlist、私有子 package 布局、app-factory API，或最小模块在不违反 ADR 0110 与上述禁止项时的其他 side-effect policy。两个 adapter 都必须保留同一 bootstrap-before-framework 顺序，不能直接指向 Typer app object 或完整 command module。

Contract tests 必须证明：preflight observation 与 ADR 0115 violation/failure path 都没有 project-caused Typer/Rich/command-module import、app/command callback 或 command registration；resource violation 只允许 ADR 0116 的 bootstrap presenter import closure 与 fixed fd2 presentation。Pass path 的可观察顺序为 preflight 恰好一次返回 PASS 后才开始 lazy import，且 help/version、known/unknown command 同样遵守顺序。PASS 后的 import failure 必须保持 bootstrap 语义；测试证据不得依赖 test runner 已经预加载的 module。最终公开 launcher/console script 一旦冻结并存在，验收必须通过该真实入口重复上述证明，不能只测内部 `bootstrap.main()`；具体测试机制不由本 ADR 冻结。[ADR 0113](./0113-feed-one-immutable-argv-snapshot-to-preflight-and-typer.md) 已冻结唯一 `tuple(sys.argv)`、exact value/order feed-through、固定 `prog_name="gezhi"`、禁用 Windows environment/`~`/glob expansion，以及关闭 Typer shell completion；[ADR 0114](./0114-exclude-argv-zero-from-raw-argv-resource-measurement.md) 已冻结 argv0 不参与资源计量，ADR 0115 已冻结三个 ceiling 的数值、单位、aggregate 与 inclusive 边界，ADR 0116 已冻结 resource violation 的完整 classification/presentation/exit。其余 bootstrap/internal 与 parser/argument failure 仍待后续决定。

该选择以更严格的入口分层、lazy import 和单独的 bootstrap 测试，换取 preflight 能在第三方 CLI framework 与完整 command graph 放大不可信参数或产生项目副作用之前真正形成门禁。它不增加依赖、配置、CLI option、diagnostic code、持久资产或模型调用，也不把 Typer/Rich 移出已冻结依赖；它只冻结何时允许项目加载和构造这些模块。
