# 在 Typer 解析前运行全 CLI decoded-argv resource preflight

所有公开 one-shot `gezhi` CLI invocation 都在 CPython 已经物化 `sys.argv` 之后、Typer 0.27.0 开始 command/subcommand/option grammar parsing、help/version handling、parameter callback 或 command callback 之前，恰好经过一次项目自有 `RawArgvPreflightV1`。这是 project-wide bootstrap seam，不由 Literature、Knowledge 或未来 Bot 单独拥有，也不以 command、`--json`、Human、help、version、known/unknown token 预先分支；它通过后才允许 Typer 继续，resource violation 则发生在 command recognition 与任何 handled adapter 之前，并由 [ADR 0116](./0116-return-2-with-one-fixed-stderr-line-for-raw-argv-resource-violation.md) 的独立 bootstrap presenter 呈现。[ADR 0113](./0113-feed-one-immutable-argv-snapshot-to-preflight-and-typer.md) 已关闭与唯一 snapshot authority 不兼容的 Typer shell-completion option 与环境输入路径，因此 completion 不是另一种公开 invocation 或参数来源。

名称中的 “Raw” 只表示这些值尚未被 Typer、CLI grammar 或领域规则解释；输入仍是 CPython 已经解码为 Python `str` 的 `sys.argv`，不是 Windows raw command line、byte sequence 或原始 quoting。Preflight 不读取 `sys.orig_argv`、不调用 `GetCommandLineW`、不重新切词或恢复已被 Python 启动层消费的 interpreter options。Windows shell/`CreateProcessW`、CPython 初始化与 argv allocation/decoding、`site`、entry stub、项目最小 bootstrap/preflight module 自身在该 seam 前发生的加载或失败均不受它保护，也不得归因为 preflight rejection。[ADR 0111](./0111-lazy-import-the-cli-framework-and-command-graph-after-argv-preflight.md) 进一步冻结 project-owned import ordering：只有 preflight PASS 后才允许 lazy-import Typer、Rich 与完整 command graph；该保证不倒推保护上述解释器、site、entry stub 或最小项目模块。

`RawArgvPreflightV1` 只拥有静态资源 ceiling 的机械检查；它不识别 token 语义，不执行 command grammar、类型/enum/number/path 转换、range 或 required-field validation、Unicode/domain normalization、configuration/environment merge、文件或 reparse probe、Git/mutex/console/cancellation 操作，也不触发模型或领域工作。Preflight 自身不写 stdout/stderr，不 prompt，不读取配置或环境来决定 limits，不写文件、日志、trace、telemetry、diagnostic、JSON、Answer、manifest 或其他持久资产，也不保存、散列、裁剪、编码或回显 argv 内容；ADR 0116 的 fd2 I/O 只属于收到无 payload violation verdict 后的最小 bootstrap presenter，不属于 preflight。[ADR 0113](./0113-feed-one-immutable-argv-snapshot-to-preflight-and-typer.md) 已冻结 invocation 在 bootstrap 内恰好一次形成 `tuple(sys.argv)`：preflight 消费完整 tuple，PASS 后 Typer 显式消费 exact `snapshot[1:]`，且项目不再读取进程参数；snapshot 只在 invocation 内存中生存，不要求也无法清除解释器继续持有的 `sys.argv`。[ADR 0114](./0114-exclude-argv-zero-from-raw-argv-resource-measurement.md) 已进一步冻结所有资源计量只覆盖 snapshot index `1..n`，index `0` 对全部 ceiling 恒无贡献；[ADR 0115](./0115-cap-raw-argv-at-128-arguments-8192-elements-each-and-16384-total.md) 冻结 suffix count `128`、单项 `8192` 个 `str` 元素与 aggregate `16384` 个元素的 inclusive ceilings、精确单位与 raw-before-domain 顺序。

只有 ADR 0115 的三个 resource predicate 中至少一项权威判定超限时，才返回 ADR 0116 无 payload 的 `RESOURCE_LIMIT_EXCEEDED` 并形成 pre-handled bootstrap resource failure；即使 argv 字面含 `--json`，也不建立 `CliResultEnvelopeV1`、Human command result、`CliDiagnosticItemV1`、`HandledCancellationWindowV1`、cancellation profile/latch 或 Knowledge outcome，不进入 ADR 0108 presentation hard fail-stop。它不得启动 command callback、configuration/path/Data Root gate、worker、child process、模型调用、commit 或 cleanup；最小 bootstrap presenter 独立尝试 exact fixed stderr、保持 stdout empty 并让 `main()` 返回 `2`。`sys.argv` shape/type 异常、snapshot allocation/`MemoryError`、preflight implementation failure、`KeyboardInterrupt`、`SystemExit` 与其他 `BaseException` 仍不得冒充 resource violation，其 presentation/exit 继续待决。

本 ADR 只批准 seam、全 CLI ownership、preflight 无 I/O/无语义解释职责与 pre-handled 边界；ADR 0111 已另行冻结 PASS 后才允许 lazy-import CLI framework/command graph 的强入口顺序，ADR 0113 已冻结唯一 immutable snapshot、exact token feed-through、固定 `prog_name="gezhi"`、关闭 Typer Windows expansion 与 shell completion，ADR 0114 已冻结 argv0 排除，ADR 0115 已冻结 argument-count/per-argument/aggregate 的数值、`len(str)` 单位、精确 aggregate、inclusive 边界与静态常量来源，ADR 0116 已冻结 resource violation 的无 payload classification、dimension non-disclosure、固定 stderr/empty stdout、completed fd2 failure 与 exit `2`。因此该特定 production rejection 已获授权；其他 bootstrap/internal、parser/argument 与 presentation failure 不继承它。每一维仍必须验证边界前一值、边界值与 `limit + 1` witness。

该选择以一个显式 bootstrap layer 和后续 feed-through 约束，换取在 Typer/command graph 继续放大不可信参数前建立可审计资源门禁；它不增加依赖、配置、CLI option、diagnostic code、持久资产或模型调用。Typer 仍是已经冻结的 CLI framework，ADR 0094 已冻结其 grammar 与 recognized raw-value handoff 的职责，ADR 0111 已冻结 preflight PASS 后才加载 framework/graph 的时序，ADR 0113 已冻结检查与解析共享同一 snapshot 的方式；本 ADR 不把领域输入错误搬回 parser，也不改变任何已冻结的 handled JSON/Human outcome。
