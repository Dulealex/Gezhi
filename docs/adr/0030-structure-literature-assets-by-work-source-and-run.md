# 按 Work、Source 与 Run 分层 Literature 资产

Literature 的正式数据根固定为 `catalog.sqlite3` 与 `works/<work_id>/`：Work 目录保存可修订身份和 Work-owned Review/Handoff，每个 `sources/<source_id>/` 保存来源描述、不可变原件、阶段当前指针，以及按 `ocr`、`canonical`、`semantic` 和 run 分层的不可变资产。Semantic terminal run 固定在 `semantic/runs/<run_id>/`，同卷 `.staging` 只用于提交前写入；成功 `result/` 必须一起包含 `reading_result.json`、`candidate_drafts.json`、`candidate_knowledge.jsonl` 与 `review_queue.json`，输入、有效提示词/Schema、逐 attempt 原始事件和审计记录与之同 run 保存。Gezhi 自有 JSON/JSONL 提供文件级 Schema identity，manifest 记录除自身外所有文件的实际哈希；Codex 原始 JSONL 保持原样而不注入字段，manifest 自身哈希由 current、Review 或 Handoff provenance 保存。`catalog.sqlite3` 只从有效 terminal manifest、正式 Candidate、`reviews/<candidate_id>/<revision>.json` 与 `handoffs/<handoff_id>/` 重建，忽略 staging 和不完整结果；格致不继承旧项目混杂的 `files/`、顶层 `ocr/paper.md`、`journal/` 或散落 sidecar。
