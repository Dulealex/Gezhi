# 在 Knowledge capture overflow 时保留精确 cap 前缀

Knowledge v1 一旦按 ADR 0077 证明某项 attempt capture overflow，该项正式资产的内容就固定为同一原始通道 byte sequence 从 offset 0 开始、长度恰好等于该路径 cap 的 exact prefix：`events.jsonl` 保留最前 `16,777,216` bytes，`final_message.txt` 保留最前 `1,048,576` bytes，第 `cap + 1` 个 witness byte 与其后 tail 都不进入正式资产。若只有一项 overflow，另一项仍按自身实际 capture 规则形成；若两项都 overflow，则分别形成各自 exact prefix，固定双文件仍必须成对安装。Writer 不添加 truncation marker、header、说明文字、BOM 或末尾 LF，不重编码、规范化、补齐 UTF-8 code point、拼接 JSON record 或寻找较早的“安全边界”；因此 prefix 可以结束在 UTF-8 sequence、JSON token 或 event record 中间，asset 的长度与 SHA-256 只针对这段原样 prefix。

这是 v1 唯一允许的 capacity-driven 主动截断例外，只能在已经观察到第 `cap + 1` 个 byte 后使用，不能用于修复普通 collector I/O failure、编码/framing/JSON/Schema/Answer validation 失败或让输出通过语义门禁。Codex `--output-last-message` 的完整 writer-private spool 继续不是正式资产；在 ADR 0079 冻结的 Job 安全收尾以及 source 关闭后，writer 只能从其 offset 0 形成上述 final prefix，并且必须在采集 `finished_at`、形成 terminal manifest 与原子提交前撤销完整 spool、越界 tail 和全部实现私有临时文件。两个正式 sink 必须能够安全关闭、读取、哈希并成对安装；任一环节失败或私有 tail/spool 无法撤销时只能留下 staging。Crash recovery 不得从 orphan source 或 oversized spool 截取 prefix、删除 tail、修复或补造资产，只能复验并补交已经具备完整有效 terminal manifest 的既有结果。本决策不增加 marker、sidecar、asset path 或 manifest/attempt 字段，overflow witness、Job stop 与 mechanical drain 由 ADR 0079 冻结；ADR 0080 已把安全收尾后的 overflow 固定为最高优先级、不可重试的 `process_error`，并映射 `failed: codex_process_failed` 与 `stage=synthesis`。Events exact prefix 必然达到 cap，因而按 ADR 0081 固定四项 token 为 `null` 且 `usage_unavailable=true`，usage consumer 不解析 prefix；同一结果也适用于不是 overflow 的 exact-cap clean EOF，不能据此反推 overflow。`TerminateJobObject` 内部退出 DWORD 与外部诊断继续后续冻结；final prefix 永不进入 Answer validation。
