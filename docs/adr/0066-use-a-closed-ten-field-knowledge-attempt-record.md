# 使用封闭的十字段 Knowledge attempt 记录

Knowledge v1 的每个 `attempts` item 都是禁止额外字段的扁平十字段 object：三个 attempt 级时间字段、一个 Windows exit code、一个封闭 failure class、四个独立 token 计数和一个必填用量完整性布尔值。Attempt 时间从 launch commitment 计到进程树、provider 捕获与该次审计收尾全部冻结，使用与 Answer 相同的 UTC 毫秒格式和独立单调持续时间；它不包含 backoff、答案验证或渲染，且因包含启动与清理开销可以超过 30-minute process watchdog。`exit_code` 只保存进程句柄已 signaled 后取得的 Win32 unsigned DWORD，未创建进程或无法取得最终 DWORD 时为 `null`。`failure_class` 只能为 `timeout`、`network`、`rate_limit`、`server_error`、`runtime_unavailable`、`process_error`、`interrupted` 或 `null`；`null` 只说明进程/provider 调用正常收尾，不证明 final output 合法。四个 token 各自只能为 `0..2^63-1` 的实际 provider/CLI 整数或 `null`，有效值独立保留，且 `usage_unavailable` 当且仅当至少一项为 `null`。该选择以不把 provider request identity 独立投影到 item/manifest、也不保存自由文本错误和 validation/rendering 结果为代价，换取能覆盖 CreateProcess 失败、部分用量、瞬时重试、用户中断与正常但输出无效等形态的稳定可验证审计记录；原样 events 内不可避免的 provider ID 只服从 ADR 0072 的不透明审计例外。

Confirmed capture overflow 复用已有 `failure_class=process_error`，不增加第八个值或 overflow flag；`exit_code` 仍按可取得的真实最终 DWORD/null 独立保存。ADR 0081 在分类完成后以正式 `events.jsonl` 的实际长度冻结五个 usage 字段：长度恰为 16 MiB 时固定为四项 `null` 与 `usage_unavailable=true`，低于 cap 时从完整正式 events 逐字段投影。Events overflow 与双 overflow 必然落 exact-cap 分支；final-only overflow 只有在 events 低于 cap 时才可能保留合法 usage。十字段集合与既有 JSON 类型均不改变。
