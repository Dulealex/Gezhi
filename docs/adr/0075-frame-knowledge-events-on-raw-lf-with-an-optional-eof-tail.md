# 仅按原始 LF 分隔 Knowledge event records

Knowledge v1 的 event framer 只有在整个 `events.jsonl` 已通过 ADR 0074 的 leading-BOM 拒绝与严格 UTF-8 门禁后才运行，并且只把原始 byte `0x0A` 视为 record terminator。空文件产生零条 record；每遇到一个 `0x0A` 都结束当前 byte slice，即使该 slice 为空；扫描结束时只有仍有非空剩余 bytes 才形成一条 EOF record，所以末尾单个 LF 不额外制造空 record，而开头 LF、连续 LF 或 LF 之间的空 slice 仍产生非法空 record。CRLF 中的 `0x0D` 原样保留在 record 内，只能作为 JSON grammar 允许的 CR whitespace 被解析，绝不与 LF 一起归一化；没有末尾 LF 的非空最后一条只要是完整 JSON object 就合法，clean EOF 本身不算 collector truncation。实现不得使用文本模式 universal newline、`splitlines()`、`\r?\n`、Unicode line separator、`strip()` / `rstrip()` 或过滤空项来改变边界。每条 record 解码后的 `str` 在只允许 JSON 的 SP、HTAB、CR 前后空白时必须被完整消费并且恰好是一个顶层 object；空或仅空白 record、任意 object 深度的 duplicate key、不完整 JSON、多个 JSON 值、array/scalar 顶层和非标准 JSON 扩展都属于 event-stream 结构失败，在安全收尾后固定为 `process_error`，但 raw asset 不改写。零条 record 本身不选择 failure class、必需事件或 Answer 终态，继续交由完整 event/terminal matrix；本决策不增加 record 数、单 record 或文件 byte 上限，逐文件 cap 与包含边界由 ADR 0077 冻结，overflow exact-prefix retention 由 ADR 0078 冻结，witness、Job stop 与 mechanical drain 由 ADR 0079 冻结，overflow classification/top terminal/nonretry 由 ADR 0080 冻结，正式 events 的 usage 长度门禁由 ADR 0081 冻结；外部诊断仍待单独冻结。

ADR 0076 已冻结 retention 保证的量词域，ADR 0077 已冻结逐文件 cap 与包含边界，ADR 0078 已冻结 overflow exact prefix 的 bytes 表示，ADR 0079 已冻结 witness、Job stop 与 mechanical drain，ADR 0080 已冻结其最高优先级 `process_error` 与顶层映射。该 prefix 不是完整 event stream，framing 成败不参与分类也不能清除 overflow；ADR 0081 的 usage consumer 不对任何 exact-cap events 执行 framing，低于 cap 时才对完整正式 events 使用本规则。该 usage-only 门禁不改变其他权威 event consumer 的既有边界，capacity overflow 也不等同于既有 collector truncation。
