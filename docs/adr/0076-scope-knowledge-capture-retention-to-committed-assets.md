# 将 Knowledge capture retention 保证限定为已提交资产

Knowledge v1 的 capture retention 保证范围只包含单个已经原子提交的 terminal Answer 中，由根级 `manifest.assets` 列出的 `attempts/NN/events.jsonl` 与 `attempts/NN/final_message.txt` 普通文件主数据流；ADR 0077 冻结的精确逐文件上限以这些正式资产的逻辑 byte length 衡量，不承诺 NTFS 分配簇、目录项或其他文件系统元数据的物理占用。Codex `--output-last-message` 必须写入当前 Answer 活跃 staging 内、正式 `attempts/NN/` 路径空间之外的 writer-private spool；该 spool 不是 manifest asset、不是 Answer validation 输入且不得进入 terminal Answer，writer 必须在形成 terminal manifest 前安全关闭并撤销它，无法撤销时只能留下 staging。该保证的量词域不包含活跃 spool 的瞬时物理峰值、无 owner 的 orphan staging、历史 Answer 的累计占用、整个 Answer 根或 Knowledge 数据根的总占用；这只表示不对这些对象作同一上限承诺，不放宽既有 I/O 安全收尾、封闭资产集合、同卷原子提交、不可变历史与保守 recovery 规则，也不授权自动清理、覆盖或改写。首版不为此引入有界 staging 卷、目录 quota、新的 final streaming 接口或 manifest/attempt 字段；timeout 与单写者 mutex 也不构成 byte quota。ADR 0077 已冻结逐文件、上界包含的精确 cap，ADR 0078 已冻结 overflow exact-prefix retention，ADR 0079 已冻结 witness、Job stop 与 mechanical drain，ADR 0080 已冻结最高优先级不可重试 `process_error` 与 `failed: codex_process_failed` synthesis 顶层映射，ADR 0081 已冻结正式 events 的 usage 长度门禁，因此 overflow terminal manifest 的十字段 usage 不再被阻塞；外部诊断继续待后续冻结。ADR 0072 的不得为通过 validation 主动截断或改写规则继续有效。未来若要求所有 staging 和历史数据的绝对物理占用上限，必须另行改变运行环境、接口或合同。
