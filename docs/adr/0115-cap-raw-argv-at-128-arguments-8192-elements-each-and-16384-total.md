# 将 raw argv suffix 限制为 128 项、单项 8192 个 Python str 元素与总计 16384 个元素

对 [ADR 0113](./0113-feed-one-immutable-argv-snapshot-to-preflight-and-typer.md) 冻结且结构合法的完整 `argv_snapshot: tuple[str, ...]`，[ADR 0114](./0114-exclude-argv-zero-from-raw-argv-resource-measurement.md) 的 suffix indices `1..n` 使用三个项目静态 inclusive ceilings：argument count 不超过 `128`，每个 suffix token 的 `len(token)` 不超过 `8192`，全部 suffix token 的 `len(token)` 之和不超过 `16384`。三个数值是代码内的 `RawArgvPreflightV1` policy constant，不来自 CLI、environment、configuration、文件、launcher 或 Bot；调整任一数值、计量单位或包含边界都必须另作架构决策。

令 `count = len(argv_snapshot) - 1`、`size_i = len(argv_snapshot[i])`（`1 <= i < len(argv_snapshot)`）、`total = sum(size_i)`。对结构合法的 snapshot，当且仅当 `count <= 128`、每个 `size_i <= 8192` 且 `total <= 16384` 三项同时成立，resource verdict 才为 PASS；任一项大于对应 limit 就是 resource violation。边界值本身全部合法：第 `129` 项、任一 token 的第 `8193` 个元素或 aggregate 的第 `16385` 个元素才越界。该三谓词的逻辑合取/析取已经冻结；[ADR 0116](./0116-return-2-with-one-fixed-stderr-line-for-raw-argv-resource-violation.md) 进一步冻结单项或多维同时超限都返回同一个无 payload variant，不公开具体维度、observed/limit 或优先级。

这里唯一的长度单位是 Python 3.11 `str` 的 `len()` 结果，也就是 token 中 Python Unicode code point 元素的数量；不是 UTF-8 bytes、UTF-16 code units、grapheme cluster、display cell 或规范化后的长度。ASCII、汉字、combining mark、NUL、control 与 surrogate 都按各自在 `str` 中的实际元素数计量；一个 astral emoji 计 `1`，由 `e` 加 combining acute 组成的 decomposed `é` 计 `2`。Preflight 不执行 UTF-8/UTF-16 encoding，所以 lone surrogate 也计 `1` 且不会在本层触发 `UnicodeEncodeError`；它是否属于合法领域输入仍由后续合同决定。

Aggregate 精确等于 indices `1..n` 的 `len(token)` 数学和，不加入 token 间 separator、原始或重建 quote、空格、NUL terminator、`prog_name="gezhi"`、launcher metadata、environment、encoding 开销或固定 overhead，也不把 [ADR 0114](./0114-exclude-argv-zero-from-raw-argv-resource-measurement.md) 排除的 `argv[0]` 重新计入。空字符串仍是一个 argument，但 per-argument size 与 aggregate contribution 都为 `0`；因此 `128` 个空 suffix token 通过 count/size/aggregate，`129` 个空 token 只凭 count 即构成 violation。

实现必须直接按完整 tuple 的 indices `1..n` 计量，只维护固定数量的 counter/state，不为了计量建立 `argv_snapshot[1:]`、长度数组、concatenated string、encoded bytes、normalized copy 或 reconstructed command line；准确保证是“不产生与输入规模成比例的额外 allocation”，而不是声称 Python 执行期间绝对零 allocation。实现可以在 verdict 已确定时短路；ADR 0116 已规定短路顺序不得改变无 payload verdict、fixed bytes 或 exit，且不成为公开 cause、dimension priority 或 observed metrics。ADR 0113 为 Typer 构造的 suffix slice 仍只能发生在 preflight PASS 之后，不属于本计量算法。

这三个 ceiling 是最早的 raw resource gate，优先于 Typer/Rich/command graph import、command/help/version/known/unknown recognition、literal `--json`、grammar、NFC、CR/LF normalization、`strip()`、encoding、Question、path、configuration 与其他领域校验。只要 raw snapshot 超过任一 ceiling，就不得为了判断“规范化后也许会变短或合法”而继续进入后层；例如一个由 `8192` 个空白元素后接 `x` 组成的单 token，即使 `strip()` 后会成为合法的 `x`，也先构成 resource violation。反过来，resource PASS 只说明 raw 规模受控，不证明语义合法：一个含 `8192` 个 emoji 或 lone surrogate 的 token 可以通过本层，再由 Question 的 `1..2000` Unicode code point、`<=8192` UTF-8 bytes 或非法字符规则拒绝；path、configuration 与 parser 规则同理。本 ADR 因而不修改 [ADR 0094](./0094-freeze-uncommitted-blocked-knowledge-ask-primary-diagnostics.md) 的领域 cause、顺序或 handled outcome。

Raw per-token `8192` 衡量规范化前整个 argv token 的 `len(str)`；Question 的 `2000` 衡量 CR/LF normalization、NFC 与 `strip()` 后规范值的 code points，Question 的 `8192` 则衡量同一规范值的 UTF-8 bytes。两个 `8192` 数字相同只是独立合同的数值巧合，不存在继承、替代或单位转换；已规范且领域合法的 Question 自身最多 `2000` code points，不会单独超过 raw per-token ceiling，但完整 invocation 仍可能超过 count 或 aggregate ceiling。Raw violation 不得映射成 `invalid_question`、`question_too_large` 或任何 Knowledge diagnostic。

本 ADR 只限制 argv representation，不建立“path/configuration/domain value 最长 8192”的字段规则：由 environment、TOML 或其他非 argv source 提供的同一领域值不受 `RawArgvPreflightV1` 计量，Windows/CPython/API 自身的 path 与 command-line limits 也不由此改变。Preflight 不解析 token；若后续 grammar 允许 `--name=value` 形态，option spelling、`=` 与 value 共同属于一个 raw token 并一起计量，separate-token 与 inline-token 表示因而可能得到不同 raw verdict，但不能据此推导任何领域字段 ceiling。PASS 也不证明 path normalization、namespace、reparse、存在性、configuration merge 或 OS 可用性。

Contract tests 必须至少覆盖 count `127/128/129`、per-token `8191/8192/8193` 与 aggregate `16383/16384/16385`；两个各 `8192` 元素的 token 在 aggregate `16384` 时通过，再增加一个非空元素时拒绝；`128/129` 个空 token 分别通过/拒绝。直接调用 preflight interface 的 constructed-tuple tests 必须完成全部字符类型与数值边界矩阵：ASCII、汉字、astral emoji、composed/decomposed `é`、NUL、control 与 lone surrogate 都按 `len(str)` 计量且不发生 encoding/normalization，并为每个 witness 加入只改变 argv0 的对照且 measurement/verdict 不变。两个真实 launcher 只重复 Windows command line 实际可表示的 boundary witnesses 与 negative-import 验收，不得要求 launcher 传递 NUL、超过 Windows 自身 command-line capacity 的 astral aggregate 或其他 OS 无法表示的 token；从 preflight observation point 起，violation path 必须证明不 lazy-import Typer、Rich 或 command graph，也不执行 parser、领域 gate、project-owned/domain I/O、配置、路径/Git probe、持久化或模型调用。Launcher、CPython、`site`、entry stub 与最小 bootstrap/preflight module 在 observation 前已经发生的加载和 I/O 仍明确位于该证明之外。另须证明 `8192` 个 raw 空白加 `x` 在 normalization 前拒绝，而 raw 规模内但违反 Question `2000 code points / 8192 UTF-8 bytes` 或非法字符规则的值只在后层拒绝。

本 ADR 仍不冻结 malformed/empty/non-`str` snapshot 的具体 internal 处置，也不授权 diagnostic code、JSON/Human handled result、持久资产或 fallback envelope。ADR 0116 已独立闭合 resource violation 的稳定分类、dimension/observed/limit non-disclosure、固定 ASCII CRLF stderr、empty stdout、fd2 completed-failure 行为与 exit `2`，因此满足本 ADR predicates 的 production rejection 已获授权；不得把该 presenter 扩成 internal catch-all。它不增加依赖、配置、CLI option、Bot-specific policy、日志、telemetry、持久资产或模型调用。

该选择以在任何语义判断之前拒绝一部分本可被后续 normalization 缩短的 raw 输入为代价，换取一个跨 Literature、Knowledge 与未来 Bot 一致、静态、可机械复验且不需要编码或复制输入的启动资源边界；领域规则仍可在 PASS 后使用更小、不同单位或更严格的合法性限制。
