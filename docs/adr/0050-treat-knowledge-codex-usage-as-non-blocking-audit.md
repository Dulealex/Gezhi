# 将 Knowledge Codex token 值作为非直接阻断的审计数据

`knowledge_answerer_v1` 为每个 Codex attempt 记录经版本化合同接受的 `input_tokens`、`cached_input_tokens`、`output_tokens`、`reasoning_output_tokens`，以及 `started_at`、`finished_at`、`elapsed_ms`、`exit_code` 与 `failure_class`；字段集合与 Reader 对齐，但由 Knowledge 自己的 terminal manifest Schema 拥有。ADR 0081 先以已复验正式 `events.jsonl` 的实际长度执行全局 usage 门禁：长度恰为 16 MiB 时即使 provider/CLI 曾提供完整 usage 也保守写四项 `null` 与 `usage_unavailable=true`，长度低于 cap 时才从正式资产运行严格 adapter；任一获准 token 字段缺失、类型错误、为负数或无法解析时，对应值为 `null`，不得估算、补零或因该 token 值本身使 Answer 失败、改变已裁决状态或触发重试。Manifest 必须保留所有 attempt，并且只有某一 token 字段在全部 attempt 中均已知时才计算该字段总和，否则该字段总计也为 `null`，不得把部分和冒充完整用量。首版不估算金额，不把 provider 自报 token 用作运行中预算闸门，也不据此提前终止 Codex；运行时正式资产复验与 usage readiness 仍进入 ADR 0068 已冻结的 classification-ready，并参与既有 timeout/interrupt 裁决。这以放弃 exact-cap clean EOF 的少量 usage 与自动成本控制换取 token 值缺失或畸形不直接产生错误、同时仍可复验的审计边界。
