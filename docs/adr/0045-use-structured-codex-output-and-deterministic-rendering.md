# 让 Codex 输出结构化语义并由 Python 确定性渲染

不可信可见文本的精确渲染边界由 [ADR 0049](./0049-escape-untrusted-visible-text-with-one-pass-commonmark-tokens.md) 补充冻结：`PlainTextToCommonMarkV1` 使用两个固定 profile、单遍 scalar-to-token 转换、全 ASCII punctuation escaping、字段前导空白保护和输入端控制字符拒绝，不允许二次解码或运行时 Markdown 修复。

Knowledge 的 Codex runtime 只输出严格版本化 JSON，不直接控制最终 Markdown、HTML、脚注、引用列表或 URL。`AnswerOutputV1` 顶层固定为 `schema_version`、`answer_status`、`answer_units`、`qualification_units` 与 `insufficiency_reason` 五个必填字段，Schema 常量为 `gezhi.answer_output.v1`；提取的完整 final assistant text 连同 JSON 前后空白最多 65536 UTF-8 bytes。确定性 Python 严格拒绝重复 key、非标准数值、float、第二个 JSON 值与未知字段，完成 Schema、状态、事实单元的 Candidate 成员资格及引用完整性验证后，再以固定规范 JSON 生成正式 `answer_output.json`；文件包含末尾 LF 最多 32768 bytes，超限不得截断、删减或用模型重试压缩。Python 只用已验证语义和 Retrieval View 的 Citation snapshot 生成用户答案；书目引用严格按 `(source_id, source_sha256)` 去重，同一 Source 的多个 Candidate 共用一条书目引用，同一 Work 的不同 Source 则保持分离，不得改用 `candidate_id`、`work_id` 或书目别名做模糊合并。参考文献集合只包含 `answer_units` 与 `qualification_units` 实际使用的 Source；未使用的 Retrieval View 项不得展示，`insufficient_evidence` 因没有 Citable Unit 而不生成参考文献区段，完整检索材料只留在 View 与 audit 中。非空集合的编号按 `answer_units`、再按 `qualification_units` 的原始顺序首次出现分配为连续 `1..N`，相同 Source 复用编号，参考文献按编号升序排列；Retrieval rank 与各类 ID 不得重排编号。每个回答与 qualification 单元都在转义后文本末尾追加恰好一个普通文本 ` [n]`，即使相邻单元复用同一 Source 也不能省略；正文 ` [n]` 引用标记不使用 Markdown 脚注、inline/reference link 或 HTML 标记。Python 还必须在 `# 回答` 后无条件生成冻结的单行 Candidate-backed 治理 blockquote，并在其前后各保留恰好一个空行以形成独立块；该系统披露不由模型控制且不附论文引用。 随后固定生成 `## 问题`，只从已验证 `question.json` 回显规范 Question；两种 Answer Status 与零 Candidate 分支都包含该不附论文引用的区段，Question 不进入 `AnswerOutputV1`。 `answered` 分支随后固定生成 `## 回答内容`，把 `answer_units` 原序逐项渲染为彼此空一行的普通段落并追加各自 ` [n]`；禁止列表、正文序号、额外标题、合并、拆分或重排，`insufficient_evidence` 不生成该区段。 当 `qualification_units` 非空时，再以 `## 局限与边界` 和无空行的 tight `- ` 列表按原序逐项渲染并追加各自 ` [n]`；空数组与 insufficient 分支完全省略该区段，列表项不得合并、分组或重排。 `insufficient_evidence` 则在问题后只生成 `## 证据不足` 与 `insufficiency_reason` 唯一映射的固定中文段落，不显示 enum、回答、局限、建议、引用或检索来源。 `answered` 的每条参考文献末尾必须以纯文本 `Source：src_<24hex>` 显示短 Source 身份，以区分书目信息相同的不同来源版本；不显示完整 hash、Work/Candidate ID、rank、路径或运行标识，完整 provenance 留在结构化资产。 作者片段只用 Citation snapshot：未知作者显示“作者未知”，明确零作者显示“无署名作者”，1–3 位按原序用 `、` 连接，超过 3 位显示前三位并追加 ` 等`；不排序、缩写、翻译或转写姓名。题名片段同样只用 Citation snapshot：非 null 题名完整保留并转义，null 显示“题名未知”；不翻译、改写、增删标点、推断或截断。年份片段只用已验证的 1000–9999 整数并渲染为四位 ASCII 十进制数字，null 显示“年份未知”；不添加后缀或从其他信息推断。外部标识符分别显示为 `DOI：<doi>` 与 `arXiv：<arxiv_id>`，两者都有时固定 DOI 在前，均缺失时全部省略；值保持已验证规范字符串，不添加 URL 前缀或参与 Source 身份。`answered` 的参考文献固定为 `answer.md` 最后区段 `## 参考文献`，按真实编号使用无空行的 ordered list；每项以 `{author}（{year}）：{title}` 开头，按存在性追加 DOI、arXiv link，最后追加 Source fragment，并只用无空格的 U+FF1B `；` 连接，因此不会产生空占位或悬空分隔符，也不补充 Citation snapshot 不拥有的出版字段。所有模型文本与外部 Citation 显示文本都按不可信纯文本进行确定性 Markdown escaping/encoding，且这种表示转换不算语义改写，链接只能从明确允许且已验证的 Citation 字段按固定模板构造。Python 不改写或扩展模型语义，无效输出不得被宽松修补；原始输出只保留为 attempt 审计资产。这样既保留 Codex 的语义综合职责，也让引用边界、展示格式和正式 Answer 发布保持可验证、可复现。
