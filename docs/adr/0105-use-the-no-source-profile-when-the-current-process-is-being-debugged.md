# 当前进程正被调试时静默使用 no-source 取消 profile

只有 [ADR 0103](./0103-require-a-read-only-conin-processed-input-capability-gate.md) 已得到 `interactive_candidate`、capability handle 已安全关闭且 ownership proof 完成后，唯一主编排线程才执行 `CurrentProcessDebuggerGateV1`。执行时 phase 必须仍为 `OUTSIDE`，且尚未建立任何 Gezhi cancellation source。该 gate 必须位于项目 native bridge DLL 的首次加载、[ADR 0101](./0101-use-a-project-owned-native-win32-ctrl-c-bridge.md) registration、[ADR 0102](./0102-normalize-inherited-ctrl-c-ignore-before-activation.md) inherited-ignore normalization、`ACCEPTING` activation 与任何领域 gate/probe 之前；`capability_absent` 已直接选择 no-source profile，不调用本 gate。

`CurrentProcessDebuggerGateV1` 通过 Python 3.11 标准库 `ctypes.WinDLL` 从 `Kernel32.dll` 解析当前进程的 `IsDebuggerPresent()`，将参数表冻结为空、返回类型冻结为 Win32 `BOOL`，并且每个适用 invocation 恰好调用一次。返回 nonzero 唯一表示 `debugger_present`，返回 zero 唯一表示 `debugger_absent`；zero 是完整合法结果，不读取或解释 `GetLastError`。DLL/symbol identity、ABI、函数签名、调用完成或返回值任一项无法证明时，路径位于正常矩阵外，不得重试、猜测、改用其他 detector、伪装成 `capability_absent` 或降级到 no-source profile。

`debugger_present` 不改写 ADR 0103 的 `interactive_candidate`，只令 cancellation profile selector 静默选择 [ADR 0104](./0104-continue-with-a-no-source-cancellation-profile-when-capability-is-absent.md) 已冻结的 `NoInteractiveCancellationBridgeV1`。因此不加载项目 native bridge DLL、不建立 Gezhi-owned handler/registration、不调用任何形式的 `SetConsoleCtrlHandler`，也不执行 inherited-ignore normalization；`source=none`、latch/observation 不存在、generation/in-flight 为零、never-registered release，以及不能产生应用级 `interrupted`/normal-return `130` 的全部不变量保持不变。`debugger_absent` 才允许继续 ADR 0101 registration、ADR 0102 normalization 与 interactive `ACCEPTING` activation；后续任一步失败仍在正常矩阵外，不能回退到 no-source。

Windows 在 console process 正被调试且 Ctrl+C signal 未禁用时可能先为 debugger 生成 `DBG_CONTROL_C`；若 debugger 处理该 exception，应用通常不会观察到 Ctrl+C，若 debugger 放行才继续作为 console signal。官方列明的 alertable-wait termination 例外也不写 ADR 0098 latch，不映射为 managed `interrupted` 或应用级 `130`；它只按该 operation 已冻结的完成/失败合同处理，无法分类或证明安全时保持正常矩阵外。Gezhi 不得用 application exception handler 处理 `DBG_CONTROL_C`，也不得安装 vectored/structured exception fallback、调用 `WaitForDebugEvent`/`DebugBreak`、用 `CheckRemoteDebuggerPresent`/PEB/environment/parent-process heuristic 扩大 detector，或把 Python `signal.signal`/`KeyboardInterrupt` 重新引入 cancellation path。该 gate 只判断 calling process 的 user-mode debugger 状态，不推断 kernel/hypervisor debugger、其他进程或未来 child 的状态。

`IsDebuggerPresent` 的单次 BOOL 返回值是本 invocation 唯一 profile-selection authority，不声称证明 debugger attach/detach 的物理线性化时间。已经反映在返回值中的状态构成本次合法粘性分类：nonzero 选择 no-source，zero 选择 interactive。任何未被该返回值反映的并发或后续 attach/detach、`DBG_CONTROL_C` disposition 变化或其他拦截行为才属于 supported baseline 之外；V1 不轮询、不追溯改判、不在领域阶段重新分类，也不晚加载或撤换 cancellation profile。若这种外部漂移后 native handler 实际收到 Ctrl+C，仍只按既有 interactive admission 处理；若没有 callback，Gezhi 不合成 observation、`interrupted`、diagnostic 或 `130`。

`debugger_present` 只作为当前 invocation 的 adapter profile-selection fact 留在内存；不得写入 CLI JSON、Human 输出、Answer、manifest、provenance、配置、任何日志/trace/telemetry、持久资产或 debugger presence/reason flag，也不得因该 fact 本身新增、删除或改写 diagnostic。后续独立成立的领域 outcome/diagnostic 仍按既有合同正常形成。未来 `doctor` 可以独立执行实时 debugger/cancellation-capability 检查，但不得从业务命令的静默行为反推本次选择。[ADR 0106](./0106-run-command-owned-children-without-a-console.md) 已冻结与 debugger selection 正交的 orchestrator-owned Codex attempt root console、process-group、stdio/handle 与 Job isolation。
