# 只从 turn.completed 投影 attempt usage

Knowledge v1 只从单轮 `codex exec --json` 的正式 events 资产中，经过 ADR 0081 长度门禁与严格事件适配器接受的唯一 usage-eligible `turn.completed.usage` object 投影每个 attempt 的四项 token；其他 event、stderr、final message、模型文本、在线 collector 状态、collector truncation/I/O 分类事实与其他 consumer 即使出现同名字段也不参与。一个 usage-eligible attempt 最多接受一个 `turn.completed`，重复 terminal event 或 JSON duplicate key 属于 provider 事件结构失败而不是 usage 缺失；没有已接受的 `turn.completed`、`usage` 缺失或不是 object 时四项全部为 `null`。合法 usage object 中四个 allowlisted 字段独立验证并保留，额外键只留在原始事件，不进入 manifest；不得跨事件求和、取最后值、取最大值或从失败事件猜测。一个完整接受的 usage 即使该 attempt 因进程未按时结束、collector failure 或其他独立事实分类为 timeout/process_error，或仅 final capture overflow，仍可保留。该选择与 OpenAI 当前非交互模式文档展示的 `turn.completed.usage` 四字段事件一致，并以不采集未文档化的失败事件用量为代价，获得无需第三方依赖、来源唯一且可审计的 Windows greenfield adapter；WSL 参考实现只验证该事件而未保存 usage，因此不能直接移植。

ADR 0081 对所有 attempts 先使用已复验正式 `events.jsonl` 的实际长度：恰为 16 MiB 时不执行 usage-directed decode、framing、JSON 或 `turn.completed` 投影，四项固定为 `null` 且 `usage_unavailable=true`，即使这是 clean EOF 且其他权威分类 consumer 已接受完整 terminal event 也不得复用；低于 cap 时才从整个不可变文件运行唯一严格 adapter。Events overflow 与双 overflow 必然落 exact-cap 分支；final-only overflow 在 events 低于 cap 时按普通逐字段规则投影，恰为 cap 时也全为 `null`。小于 cap 的全流一旦发生 BOM、UTF-8、framing、JSON、duplicate-key、重复 terminal event 或其他结构失败，不得保留坏点之前的 provisional usage；四项全为 `null`，而分类仍按既有规则决定。
