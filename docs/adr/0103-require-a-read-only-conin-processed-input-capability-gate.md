# 用只读 CONIN$ 与 processed-input 建立 Ctrl+C 能力门禁

Parser 已完成 grammar、保留 recognized raw values，且尚未启动、执行或 commitment 任何领域 gate/probe 时，`ConsoleCancellationCapabilityV1` 只通过 Win32 console input buffer 判断 native interactive cancellation 候选。唯一主编排线程使用 `CreateFileW(L"CONIN$", GENERIC_READ, FILE_SHARE_READ | FILE_SHARE_WRITE, NULL, OPEN_EXISTING, 0, NULL)` 打开 non-inheritable handle；只有返回值不等于 `INVALID_HANDLE_VALUE` 才取得 handle。随后以 `GetConsoleMode` 取得 input mode；只有其返回 nonzero 后才可读取已初始化的 mode，且 `mode & ENABLE_PROCESSED_INPUT != 0` 时结果才是 `interactive_candidate`。不得用 `GetStdHandle(STD_INPUT_HANDLE)`、TTY/isatty 猜测、环境变量、terminal 品牌、窗口句柄或 stdin 内容替代该证明。

字面 `CONIN$` 直接指向 attached console 的 input buffer，因此 stdin 被文件、pipe 或 NUL 重定向不降低已经成立的 interactive candidate；Windows Terminal、ConPTY 与其他 host 也不按品牌建立例外，只要同一 `CONIN$`/`GetConsoleMode` 证明成立就使用相同结果。无法打开 `CONIN$`、`GetConsoleMode` 返回失败，或 `ENABLE_PROCESSED_INPUT` 未设置，都是 `capability_absent`，不得注册或激活 ADR 0101 native bridge，也不得把 Ctrl+C 键盘输入事后解释成 cancellation；该结果按后续 ADR 0104 选择无 source 的逻辑取消生命周期并继续命令。

Capability handle 从创建起登记为 adapter-owned、non-inheritable 临时资源；若已经取得 handle，无论 mode 结果如何，都必须用 `CloseHandle` 完成并证明关闭后才能离开 classifier。Open/query 的确定失败或 bit-off 可以形成 `capability_absent`，但 close 返回失败、handle ownership/identity 不确定、mode value torn/未初始化或 classifier 自身状态无法证明时位于正常矩阵外，不能伪装成无 console、继续领域工作或启动子进程。Capability 结果只存在于当前 invocation 内存，不进入 CLI diagnostic、配置、Answer、manifest、provenance 或持久资产。

本门禁只读取 input-buffer mode，绝不调用 `SetConsoleMode`、修改任一 mode bit、恢复 snapshot、消费 input record 或保持 console handle 到领域阶段。External host/process 在证明后修改 `ENABLE_PROCESSED_INPUT` 或切换 attached console，属于 supported baseline 之外；V1 不轮询、占有或锁定共享 console buffer，也不声称可以阻止这种外部漂移。Debugger 状态不由本门禁冻结；后续 ADR 0105 只对本门禁已经返回的 `interactive_candidate` 执行一次当前进程 debugger gate，不改写 capability 结果。已经反映在该唯一 BOOL 返回值中的 debugger 状态属于合法 profile selection，未被返回值反映的并发或后续变化才属于外部漂移。

`interactive_candidate` 只有在 capability handle 已安全关闭后，才先进入 [ADR 0105](./0105-use-the-no-source-profile-when-the-current-process-is-being-debugged.md) 的 `CurrentProcessDebuggerGateV1`：`debugger_present` 静默建立 `NoInteractiveCancellationBridgeV1`，只有 `debugger_absent` 才依次进入 ADR 0101 registration/`ARMED_PASS_THROUGH`、ADR 0102 `SetConsoleCtrlHandler(NULL, FALSE)` normalization 与 interactive `ACCEPTING` activation。`capability_absent` 不执行 debugger gate 或 ADR 0102 normalization，而是直接按 [ADR 0104](./0104-continue-with-a-no-source-cancellation-profile-when-capability-is-absent.md) 建立 no-source profile。只有所选 profile 的 activation proof 完成后，才允许启动、执行或 commitment 第一项领域 gate/probe；[ADR 0106](./0106-run-command-owned-children-without-a-console.md) 已另行冻结之后每个 orchestrator-owned Codex attempt-root launch 的 no-console/no-process-group 与 Job proof。
