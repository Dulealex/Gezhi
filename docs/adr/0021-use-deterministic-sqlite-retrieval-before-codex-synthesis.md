# 在 Codex 合成前使用确定性 SQLite 检索

Knowledge 以 SQLite Candidate Registry 为事实源，并用可重建的 FTS5 `unicode61 remove_diacritics 2` 与 `trigram case_sensitive 0` 索引支持英文、技术词、中文二字和子串检索。Python 只从 `intake_status=active` 的 Candidate 中确定性选择最多 12 条：索引内容限于 Candidate 规范陈述、来源术语、Descriptor 名称/来源术语和 Work 标题，短证据摘录只在入选后提供；问题经 NFKC/casefold 与安全字面量拆分，Han 文本分别形成二字和三字窗口，两路字段等权 BM25 各取 48 条，再以精确 `RRF k=12` 合并并用 `candidate_id` 处理并列。Candidate 类型、年份、风险和审核时间均不加权，零匹配返回 `insufficient_evidence`；任一 FTS 不可用或运行失败都明确终止，不静默单路降级。冻结的 Retrieval View 只含 Candidate 正文、最小来源书目信息、短证据摘录、Evidence/Descriptor 引用、支持关系、风险与必要治理披露，不暴露数据库、PDF、完整 Reading Result、私人审核备注或未入选 Candidate；Codex 不能访问数据库、调用检索工具或参与重排，Python 在发布前校验所有事实性引用都属于本次视图。首版不使用 Embedding、向量数据库或模型重排，精确原子化、复杂度和错误规则以 [Knowledge Answerer v1 合同](../contracts/knowledge-answerer-v1.md) 为准。
