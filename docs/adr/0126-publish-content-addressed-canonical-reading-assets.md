# 发布内容寻址的 Canonical Reading Asset

Canonicalize 是 Literature-owned 的确定性深模块，只消费已经完整验证并由 `ocr/current.json` 唯一选中的 OCR success，绝不调用 Codex、读取非 Active Source 或把 MinerU 私有格式暴露给下游。每个 Source 使用 `canonical/runs/.staging/<canrun_uuidv4>/`、`canonical/runs/<canrun_uuidv4>/` 与 `canonical/current.json`；成功 run 恰好发布 `document.md`、`blocks.jsonl`、`images/`、`schema.json`、`provenance.json` 和最后写入的 `manifest.json`。Manifest 绑定 Work、Source 完整 SHA-256、OCR run/manifest/input fingerprint、Canonicalizer profile、Schema snapshot、逐资产实际 bytes 与 input fingerprint；current 同时绑定 run/manifest、Source、input fingerprint 与 `canonical_content_sha256`。相同 input fingerprint 的唯一有效 success 必须复用；完整 orphan 只补 non-replacing rename/current，partial、unsafe、歧义、碰撞与无法证明的 replace 均保留证据并停止，绝不覆盖上一成功结果。精确文件、字段、规范化、身份、预算和恢复规则由 [Canonical Reading Asset v1](../contracts/canonical-reading-asset-v1.md) 冻结。

Canonical 文本先做 CRLF/CR→LF、Unicode NFC 和 Python 3.11 `str.strip()`；NUL、非配对 surrogate、空的 Evidence Block 和解码替换均无效，其他内部空白与 Unicode 原样保留。Native text 按页和一个或多个空白行确定性分段；MinerU 3.4.4 只以已经验证的 `source_content_list_v2.json` 页数组作为结构化正文 authority，按外层页序、item 顺序和类型内顺序映射为 `heading|paragraph|list_item|table|figure_caption|figure_text|equation|other_text`，不从 `source.md` 猜正文，也不拼接彼此未证明等价的 vendor 文档。空页以 `document.md` 的 `<!-- gezhi-page:<0-based index> -->` 标记和 provenance 的 page count 显式保留，但不制造空 block；全部页面零文本、超过 4,096 页、4,096 个文本 block、单 block 1,048,576 UTF-8 bytes、任一 Canonical 文本/JSON 文件 67,108,864 bytes、4,000 张图片、单图 67,108,864 bytes 或图片合计 2,147,483,648 bytes 均为 `canonicalization_failed`，不发布 success。

`blocks.jsonl` 每行是 closed `gezhi.evidence_block.v1`，固定含 `block_id、order、kind、text、heading_path、page_index、bbox、image_path、schema_version`；order 从 0 连续，page 是最早 0-based 来源页，Native 的 `bbox=null` 表示整页，MinerU bbox 规范为四个无歧义 decimal string。`image_path` 为 null 或 `images/<完整图片 SHA-256>.<jpg|png>`；Canonical 只流式复制被结构化正文引用、通过 magic/边界/普通文件验证的图片，相同 bytes 去重，路径 NFC、POSIX、UTF-8 bytes 排序并拒绝 Windows casefold 冲突。`block_id=blk_<24hex>`，完整 hash 前像是除 `block_id` 外上述来源位置、类型、规范文本、标题路径、图片路径与 order 加 `schema_version=gezhi.evidence_block_identity.v1` 的 CanonicalJsonV1 bytes；短 ID 对应不同完整 hash 为整个 run 失败。`canonical_content_sha256` 严格使用 Candidate Knowledge v1 的 `document.md`、`blocks.jsonl` 与全部 Canonical image 实际 bytes 算法，不含 Work/Source/OCR/Canonical run ID、路径、时间、工具或 Schema snapshot，因此相同内容的可审计重跑保持相同 Evidence Pointer。
