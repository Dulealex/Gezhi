# 使用版本化 TOML 与环境秘密

Configuration 只对全部 Context root strings 做无 I/O 的词法隔离验证；进入 Data Root gate 后，每个命令只 safe-open 自己消费的 root，禁止为了验证全局物理隔离而探测其他 Context roots。V1 以严格 no-hidden-alias policy 补足该边界：8.3 short name、SUBST、额外 drive-letter、volume mount 或其他隐藏 filesystem alias 一经 safe-open 证明即为 `data_root_unsafe`，而不是让所有 Bot 在运行时互相依赖。

`gezhi.config.v1` 的所有 Context root 必须在规范化 Windows path namespace 上两两不同且互不嵌套。任一 root 都不得等于或包含项目根 `E:\Gezhi`；项目内 root 必须是 `E:\Gezhi\data` 的严格后代而不能直接等于该共享容器，项目外的本机 root 仍允许。该规则也约束 future Context。全部 source 合并后，能够无文件系统 I/O 纯词法归一为本机 DOS 绝对路径的 final values 若已违反该规则，Configuration gate 选择 `configuration_invalid`；文本通过后，只有 safe open 才能证明的隐藏别名、真实对象重合/嵌套或物理边界冲突由 Data Root gate 选择 `data_root_unsafe`。Configuration gate 不为此访问文件系统。

格致使用完整内置安全默认值作为最低优先级基线；Git 管理且不含秘密的 `config/default.toml` 是必须存在的版本化 partial patch，Git 忽略且不含秘密的 `config/local.toml` 是可选的版本化 partial patch。两份 active TOML 都必须声明符合 lowercase ASCII `gezhi.config.vN`（`N` 为无前导零正整数）的 string `config_version`，当前只支持 `gezhi.config.v1`，且 default/local generation 必须相同。CLI 参数与 `GEZHI_*` 环境变量是不携带也不能设置 `config_version` 的当前程序 generation partial raw patch；version metadata 不进入 final runtime config 或业务资产。所有 source 按 CLI、`GEZHI_*`、local TOML、default TOML、程序安全默认值的顺序覆盖。每个 patch 只验证自己要求与实际提供的字段，未知字段拒绝；全部 source 通过后，closed Schema 对每个 leaf 选择最高优先级第一个 present value。Nested table 只覆盖 present leaf，scalar/array 原子替换，禁止拼接、逐项 merge、null、unset、delete marker 与 tombstone；空字符串是 present value。Final required/cross-field 规则只对合并结果执行。`gezhi.config.v1` 的 external runtime leaf 仅为 nonempty string `literature.data_root` 与 `knowledge.data_root`，完整内置默认值分别为 `E:\Gezhi\data\literature`、`E:\Gezhi\data\knowledge`；unknown Context/table/leaf 拒绝，未来 Context 必须升级 generation 显式扩展。除上一段已经归 Configuration gate 的纯词法 cross-field isolation 外，两项 path string 的 namespace/filesystem policy 由 Context Data Root gate 拥有：只支持本机 non-remote drive-absolute/local extended DOS，项目外本地根允许，relative/UNC/WSL UNC/remote mapping/device/Volume GUID/ADS 等 unsafe namespace 拒绝且不自动创建缺失目录。Model、reasoning、Codex version、timeout/backoff、attempt/retrieval/capture/Schema/cap 与其他 role policy 不是配置 field，source 提供时作为 unknown field 拒绝。Python 3.11 `tomllib` 负责读取 TOML，Pydantic 严格拒绝 unknown supplied field；missing/non-string/grammar-invalid version 无效，grammar-valid unsupported generation 或 active TOML mismatch 不兼容。秘密只允许来自进程环境或 Git 忽略的 `.env`，但 `.env` 的加载方式不属于非秘密 merge，后续单独冻结。Codex 登录仍由自身凭据存储管理。运行时不修改 external config；每个 Context 自己的运行合同决定是否保存只读 role audit 资产，Knowledge 的 `effective_config.json` 由 role descriptor 生成而不是 user settings dump。旧 YAML 和 PyYAML 兼容层不进入格致。Source-specific CLI/env name 仍由 concrete configuration contract 继续冻结。
