# 将有效配置保存为 manifest-bound 安全资产

Knowledge v1 在每个 Answer 根保存封闭根级 `effective_config.json`，只含独立拥有的 30-minute attempt timeout、95-minute attempt-window limit、10/30-second retry backoff schedule 与 `gezhi.knowledge_answerer_effective_config.v1` Schema identity；最大三次 attempt 由退避数组长度派生，不重复保存。该文件使用确定性紧凑 JSON UTF-8 bytes 加一个 LF，manifest 通过固定 path、Schema identity、实际 byte length 与覆盖最终 LF 的 SHA-256 绑定它，不内嵌第二份 object 或重复 config hash。ADR 0094 后续将 V1 external configuration 收窄为真实 machine/deployment facts，因此本资产不再解释为用户 settings 的脱敏投影：它必须从 immutable `knowledge_answerer_v1` role descriptor 正向生成，在 Answer 身份生成前完成验证与 canonical serialization，并在 ID 后原样写入。Model、reasoning、Codex CLI、attempt count、检索/捕获/Schema/cap 与其他 role policy 均不成为配置键；Data Root、来源层、环境、问题、凭据或其 hash/长度/存在标记也不进入本资产。该选择以不保存完整应用 settings、deployment config 和来源层为代价，避免双事实源与假配置旋钮，同时让四种终态和零候选 Answer 都能复验实际绑定的 Knowledge runtime 数值。
