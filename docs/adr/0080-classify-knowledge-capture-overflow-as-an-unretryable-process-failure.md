# 将 Knowledge capture overflow 分类为不可重试的 synthesis process failure

Knowledge v1 只有在 ADR 0079 的 capture-finalization 安全边界全部成立，并同时结清 [ADR 0106](./0106-run-command-owned-children-without-a-console.md) 冻结的 stdin/stdout、child-side duplicates、process/thread 与 Job handle ownership 后，才允许把 confirmed overflow 形成 terminal attempt：root handle 已 signaled、Job active-process count 为零、stdout pipe 已到 EOF、final source 已关闭并完成权威复验、两个正式 sink 已安全关闭/读取/哈希并成对安装、spool/tail/私有临时文件已撤销，而且全部 writer/collector/monitor 已 join、不会再产生新的 latch。任一条件无法证明时，即使已经观察到 overflow 也只能留下 staging，不得写 `failure_class`、terminal manifest 或伪造干净终态。

到达该唯一分类线性化边界后，编排器对 events 与 final 两个不可逆 overflow latch 做 OR；任一为 `true`，该 attempt 就固定为 `failure_class=process_error`，不比较 witness、timeout、用户中断、provider/runtime failure、exit 或其他 lifecycle/event 事实的先后。Timeout/interrupt stop 后 mechanical drain 才读到 events witness，或 root 正常退出、Job 已空后 final 权威复验才发现超限，都仍由 overflow 胜出；`TerminateJobObject` 调用成功或失败本身不是分类点。调用失败但最终 Job 已空且全部安全条件成立时仍按 overflow 分类，调用成功但安全条件不能证明时仍只留 staging。正确实现必须在 item freeze 前完成 post-close 检测；若 freeze 后还能产生新 latch，说明收尾边界不真实，在原子提交前发现时必须放弃 terminalization 并留下 staging，不能回写 item。

Overflow `process_error` 是该 active attempt 的最高主终止类别，覆盖同时或先后观察到的 `timeout`、`interrupted`、`network`、`rate_limit`、`server_error`、`runtime_unavailable`、provider/exit/event/lifecycle failure，并且不可自动重试。编排器在 overflow item freeze 后的同一串行状态转换中关闭 attempt window，禁止 backoff、下一次 launch commitment、Answer validation 与结果发布，并锁存 `status=failed`、`error.code=codex_process_failed`、`error.stage=synthesis`；当前 overflow item 必须是 `attempts` 最后一项，更早 items 只能是已经合法触发重试的瞬时失败。根级资产复用既有 `failed: codex_process_failed` 矩阵：P4 与 C 必须存在，O 禁止，Candidate 为 `1..12`，attempts 为 1–3 项；final exact prefix 永不成为 Answer validation 输入。

本决策复用既有七值 `failure_class`、15 项 error code 表与四值 stage，不增加 overflow 字段、marker、sidecar、retryable 标记或第 16 个 manifest code。`exit_code` 仍按真实最终 Win32 DWORD/null 规则独立保存，不因 overflow 被清除；四项 token、`usage_unavailable` 与 `usage_totals` 由 ADR 0081/0070 已闭合，因此安全边界、分类与 usage 唯一复验完成后可以形成完整十字段 item 和 terminal manifest。正式资产长度恰等于 cap 是 overflow exact prefix 的必要结果，却不是 overflow 的充分证明，因为 clean EOF 也可恰好等于 cap；validator、recovery 与未来 CLI 不得仅凭长度反推 overflow。ADR 0081 仅把该长度作为 usage-only 保守门禁，不能据此改变本 ADR 的分类、优先级或顶层映射。ADR 0092 已冻结 committed overflow 共用的 primary `knowledge.ask.codex_process_failed.v1`；哪个通道 overflow、可报告的观察下界与人用文案仍留给 supplemental diagnostic 合同。

本决策不增加第三方依赖、配置键或持久资产，也不冻结 `TerminateJobObject` 的内部退出 DWORD、轮询 cadence 或 overflow-specific supplemental 格式；实现继续只需现有 Python 标准库与 Win32 adapter。
