# 在语义层严格解码 Knowledge attempt 捕获

Knowledge v1 继续把两个 attempt capture 当作任意 `application/octet-stream` 原始 bytes 保存，asset identity pass 不执行任何解码；只有 event adapter 读取 `events.jsonl`，terminal validator/recovery 按 ADR 0081 对低于 cap 的正式 events 重算 usage，以及 Answer validator 读取最后一个 `failure_class=null` attempt 的 eligible `final_message.txt` 时，才进入严格 UTF-8 语义门禁。门禁先拒绝文件绝对 offset 0 的三个 bytes `EF BB BF`，不得以 `utf-8-sig` 或其他方式剥离 BOM；随后必须对完全相同的原始 byte sequence 执行等价 `decode("utf-8", errors="strict")`，禁止默认/locale/Windows code page、编码自动探测、fallback、转码、Unicode normalization，以及 `replace`、`ignore`、`surrogateescape` 或其他非 strict error handler，也不得把 raw bytes 直接交给可能自动探测 BOM、UTF-16 或 UTF-32 的 JSON API。该规则禁止解码器合成替换字符，不会仅因原始 UTF-8 合法编码的 U+FFFD 或 JSON string 内合法的 U+FEFF 而拒绝内容；它们仍服从后续 JSON 与 Schema 规则。Events 的 leading BOM 或 UTF-8 解码失败属于 event-stream 结构失败，在捕获安全收尾后固定为 `process_error`，原始 asset 仍保留且不得重试；eligible final 必须先按原始文件 byte length 执行既有 0/65536-byte 门禁，再严格解码，leading BOM 或解码失败得到 `failed: answer_output_invalid`，而正常结束 attempt 的 `failure_class` 仍为 `null`。更早或任何非空 failure attempt 的 final 不进入 Answer validation，也不得因其编码改写已有分类。该选择以拒绝可被宽松解析器修复的输入为代价，换取跨机器确定性和 byte-for-byte 审计；event record framing 由 ADR 0075 冻结，两个 capture 的逐文件 cap 与包含边界由 ADR 0077 冻结，overflow exact-prefix retention 由 ADR 0078 冻结，witness、Job stop 与 mechanical drain 由 ADR 0079 冻结，overflow classification/top terminal/nonretry 由 ADR 0080 冻结，正式 events 的 usage 长度门禁由 ADR 0081 冻结；外部诊断仍待单独决定。

ADR 0076 已冻结 retention 保证只量化单个已提交 terminal Answer 的正式 capture 资产；精确 cap 与包含边界见 ADR 0077，overflow prefix 见 ADR 0078。Prefix 允许结束在 UTF-8 sequence 中间；它的编码成败不参与 ADR 0080 的 `process_error` 分类，也不能清除 overflow。Final prefix 不进入 Answer validation；events exact prefix 必然达到 cap，ADR 0081 的 usage consumer 不对任何 exact-cap events 执行本门禁，低于 cap 时才对完整正式 events 严格解码。该 usage-only 限制不禁止 non-overflow exact-cap clean EOF 为其他权威终态分类目的进入 event adapter，本语义门禁也不处理 writer-private spool。
