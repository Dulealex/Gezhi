# 将 Knowledge attempt 原始捕获统一标记为二进制流

Knowledge v1 的每个 `attempts/NN/events.jsonl` 与 `attempts/NN/final_message.txt` asset item 都必须使用逐字精确、无参数的 `media_type=application/octet-stream`，同时必须省略 `schema_id` key 而不是写成 JSON `null`。该 identity 描述 collector 实际保留的任意原始 bytes，不声明内容已经符合 JSONL、纯文本、UTF-8 或 Answer Schema；因此空、合法、畸形与截断捕获在所有允许终态中都保持同一 media identity，writer、validator 与 recovery 不得根据扩展名、内容、长度、failure class 或 terminal status 改成 `application/jsonl`、`application/x-ndjson`、`application/json`、`text/plain`、带 `charset` 的值、大小写变体或其他类型。资产 identity pass 只复验固定路径与成对存在、精确 media string、实际 byte length 和 SHA-256，不执行解码、BOM、换行、JSONL 或 final Answer 验证；完成该 pass 后，terminal validator 与 recovery 仍按 ADR 0081 对低于 cap 的正式 events 运行 usage semantic pass。文件名和 ADR 0072 继续绑定捕获通道，event adapter 与 Answer validator 在独立语义层决定内容能否使用。该选择以 media label 较为通用为代价，避免把失败现场错误标记成已经符合预期格式；语义层编码验收由 ADR 0074 冻结，event record framing 由 ADR 0075 冻结，逐文件 cap 与包含边界由 ADR 0077 冻结，overflow exact-prefix retention 由 ADR 0078 冻结，witness、Job stop 与 mechanical drain 由 ADR 0079 冻结，classification/top terminal/nonretry 由 ADR 0080 冻结，正式 events 的 usage 长度门禁由 ADR 0081 冻结；外部诊断仍待单独决定。未来若改变这两个路径的 media identity 必须升级 Answer manifest Schema。

ADR 0076 已把 retention 保证范围限定为单个已提交 terminal Answer 的上述正式资产；精确 cap 与包含边界已由 ADR 0077 冻结，overflow exact-prefix retention 已由 ADR 0078 冻结，witness、Job stop 与 mechanical drain 已由 ADR 0079 冻结，classification/top terminal/nonretry 已由 ADR 0080 冻结，正式 events 的 usage 长度门禁已由 ADR 0081 冻结；外部诊断仍待决定。Prefix 可以语义不完整，但不改变本 ADR 的不透明 media identity 或 ADR 0080 的 `process_error`。
