# 要求顶层 Answer error 存在性矩阵

Knowledge v1 的 terminal manifest 在四种运行终态下都必须包含顶层 `error`，不得省略；`succeeded` 与 `interrupted` 时严格为 JSON `null`，`blocked` 与 `failed` 时严格为非 `null` JSON object。成功前发生的失败重试只属于 attempt 审计，不能成为成功 Answer 的顶层错误；首版 `interrupted` 只表示用户主动中断，`status` 已完整表达终因，因此不再制造 manifest `user_interrupted` 错误码或提升中断前的 attempt 失败。该固定 envelope 能把合法无错误与字段遗漏区分开，并让 validator 与 crash recovery 机械拒绝状态/错误不一致；代价是以后若需要多种中断原因或顶层中断阶段，必须升级 manifest Schema。error object 的内部字段、错误码全集与 stage 枚举已经由 ADR 0058–0060 冻结；本次 invocation 的 CLI 外部载体已由 ADR 0089 冻结，共享 diagnostic item/profile 已由 ADR 0091 冻结，committed Answer 的十五项 error primary 与独立 CLI `knowledge.ask.user_interrupted.v1` primary 已由 ADR 0092 冻结，no-commit outcome/result 分类与正常 JSON exit 已由 ADR 0093 冻结，no-commit blocked、failed 与 interrupted primary/context 已分别由 ADR 0094、ADR 0095、ADR 0096 冻结，跨 outcome 静态优先级已由 ADR 0097 冻结，cancellation/identity cutover 已由 ADR 0098 冻结，no-commit drain/cleanup 安全证明已由 ADR 0099 冻结；supplemental、Human 文案和任何持久诊断资产仍独立待定，且不得成为 ADR 0083 所禁止的额外 v1 顶层 key。
