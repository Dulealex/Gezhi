# 用单一取消锁存与原子 pre-ID barrier 切分 Answer 生命周期

`knowledge.ask` 的唯一受支持用户取消源是当前 handled cancellation window 内由 command-owned bridge 接受的 Ctrl+C；bridge 只可向本次 one-shot cancellation latch 原子锁存一次取消事实及其首次 `observed_monotonic_ns`，callback 不得直接选择 outcome、构造 diagnostic、抛异步业务异常、终止进程、释放 ownership、写文件或执行 cleanup，重复取消不得改写该事实，Ctrl+Break、console close/logoff/shutdown、worker/Codex 状态、子进程退出、外部强杀或进程消失都不是 V1 写入者，该 invocation 在 ID 前后始终复用同一个 latch，observation 只作进程内仲裁且不进入 diagnostic 或持久资产。

唯一 Knowledge 编排器在 handled adapter 入口、每个 pre-Answer gate 进入前与返回后、多项 gate 的安全有界单元之间（包括 enumeration 与相邻 orphan candidate/recovery 之间）、最终 pre-ID barrier，以及任何 no-commit outcome 最终锁存前消费 latch；取消 transition 与每个下一 gate、candidate 或其他新业务工作的 commitment 必须由同一 command-owned 串行状态转换二选一，不能 `read false -> start work`，取消先赢后只允许排空此前已经赢得 commitment 的 in-flight operation 并执行证明安全边界所必需的 cleanup，在途操作独立发生并安全确认的 ADR 0095 failed cause 仍参与 ADR 0097 仲裁，但取消请求、响应取消的 stop request 或预期 cancellation completion 本身不得制造新的 failed candidate，最终 no-commit outcome 也只在 ADR 0099 的 typed live-resource ledger 清零且 `NoCommitSafeBoundaryV1` 成立后于同一仲裁域原子锁存。

最终 cancellation snapshot 与规范 `answer_id` 的成功生成、验证和锁存必须属于同一个 command-owned 串行状态转换，不允许 `check cancellation -> generate ID` 间隙：取消先线性化则绝不安装 ID 并按 ADR 0097 进入 no-commit 仲裁，预生成 UUID bytes 在成功锁存前也不叫 `answer_id`；ID 先线性化则 Answer 生命周期不可逆开始，即使 `started_at` 尚未采集或 staging 尚未创建，后来取消也必须尝试形成并提交完整 `status=interrupted` Answer，提交失败仍走 ADR 0095 或正常矩阵外路径；首次 monotonic observation 只供既有 ID 后 deadline 仲裁消费，不得用 callback 调度顺序、异常到达顺序、wall clock 或事后 monotonic 时间比较重新解释 pre-ID cutover，barrier 内 UUID 生成或验证失败也不得临时冒充 `pre_answer_formation_failed`，当前 V1 没有获准 cause 时保持正常矩阵外。后续 ADR 0100 已冻结 handled cancellation window 在 parser grammar 成功后、第一领域 gate 前开始，并在 immutable command-state seal 后完成所选 profile 的 zero-in-flight/source-specific release 才进入 presentation；[ADR 0104](./0104-continue-with-a-no-source-cancellation-profile-when-capability-is-absent.md) 的 no-source profile 没有 latch 写入者、callback 或 registration。
