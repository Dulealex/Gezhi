# 使用封闭阶段前缀与两个原子对约束 Answer 根级资产

Knowledge v1 的 terminal Answer 根级业务资产只允许形成连续前缀 P0–P4，并可按封闭条件附加两个原子对：P0 只有所有终态必有的 `effective_config.json`；P1–P4 依次增加 `question.json`、`retrieval_query.json`、`retrieval_audit.json` 与合法且未超预算的 `retrieval_view.json`。任何前缀不得跳项或包含当前失败资产；`retrieval_view_too_large` 固定停在 P3，超限的 would-be View 不以正式文件发布。C 是 `{prompt.txt, schema.json}`，只能在 P4、非零 Candidate 且完整 synthesis 调用包通过复验后成对出现；零 Candidate、retrieval 终态与 `synthesis_input_invalid` 均不保存 C。O 是 `{answer_output.json, answer.md}`，当且仅当 `status=succeeded` 时成对出现，其他终态两项都禁止。每项资产与每个原子对只有在活跃 staging 的实现私有临时位置形成、关闭，并通过 byte length、SHA-256、Schema/media identity 与全部后置条件验证后，才能取得最终根级名称；当前资产失败只保留最后一个完整前缀，无法清除临时或半完成文件时不得形成 terminal manifest，只留下 staging。该规则让 retrieval 失败、零 Candidate、Codex 重试、validation/rendering 失败与用户中断都能由有限集合机械验证，无需在 manifest 复制阶段或 Candidate 数；它细化 ADR 0031，并取代 ADR 0034 对每个 Knowledge Answer 无条件保存 `prompt.txt` 的要求，改为每个实际 launch attempt 绑定同一完整 C 对。P4/C 之后实际 commitment 的 attempt 子资产由 ADR 0072 以固定双文件规则闭合，并由 ADR 0073 固定统一的二进制流 media identity，不属于根级阶段前缀。

Confirmed capture overflow 不新增根级矩阵分支，复用 `failed: codex_process_failed`：P4 与 C 必须存在，O 禁止，Candidate 为 `1..12`，attempts 为 1–3 项；最后一项是 ADR 0080 的 overflow `process_error`，更早项只允许合法瞬时重试。Final exact prefix 不是 O，也不得进入 Answer validation。
