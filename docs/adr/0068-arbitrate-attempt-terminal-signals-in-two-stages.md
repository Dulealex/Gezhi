# 分两阶段唯一裁决 attempt terminal signals

Knowledge v1 对每个已 commitment attempt 只保存一个 final `failure_class`，并由单一编排器执行“生命周期完整性门禁，再裁决主终止原因”的封闭算法。无法确认进程树终止或 collectors 关闭时不得形成 terminal manifest；最终达到安全收尾边界但发生 CreateProcess、最终 DWORD、进程树/job、collector I/O 或事件流结构失败时固定为最高优先级 `process_error`，覆盖 timeout、provider 故障与用户中断且禁止重试，单个 usage 值缺失或畸形除外。完整性通过后，以固定 monotonic deadline、用户取消 observation 与进程/provider/exit/usage 全部可分类的 attempt classification-ready 边界比较先后，同刻由 interrupt 优先；二者都未先终止时才按 `runtime_unavailable > rate_limit > server_error > network` 解析获准 provider 终态证据，随后以未知非零 exit 回退 `process_error`，以无故障且 exit 0 得到 `null`。Item 一经冻结不得回写；编排器必须紧接着原子决定重试、进入 validation 或锁存 Answer 顶层终因。只有尚未锁存顶层终因的 retry/backoff/validation/rendering 状态可被后来取消，非重试故障或耗尽终因一经锁存就不能被 manifest 写入期间的晚到取消覆盖。该选择以某些用户中断在本地生命周期同时失败时最终显示为 process failure 为代价，保证 retry、安全收尾和 terminal manifest 都由唯一、保守且可实现的分类函数决定。

上述第二阶段 signal/exit 比较只适用于两个 overflow latch 都为 false 的 attempt。ADR 0079/0080 对 overflow 复用且加强同一不可放宽的 Job-empty、pipe EOF、final post-close、sink pair、私有清理与 collector/monitor join 安全门禁；门禁通过后先对两个 latch 做 OR，任一为 true 就直接得到最高优先级 `process_error`，覆盖 lifecycle、timeout、interrupt、provider/runtime 与 exit facts，不进入第二阶段且禁止重试。该 item 的 usage 按 ADR 0081 冻结后，编排器再冻结 item，并在同一串行转换锁存 `failed: codex_process_failed` 与 `stage=synthesis`；安全门或 usage 唯一复验失败仍只留 staging。
