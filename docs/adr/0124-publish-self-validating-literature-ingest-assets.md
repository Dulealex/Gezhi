# 发布可自证的 Literature ingest 资产

Windows V1 的 `literature add` 以文件资产而不是 SQLite row 作为 ingest 权威事实。一个已提交 Work 使用 `work.json` 绑定规范 Work ID；`identity/revisions/idrev_<24hex>.json` 保存 DOI、arXiv ID 与 Citation 的完整内容寻址快照，`identity/current.json` 只原子指向一个已验证 revision。每个 `sources/<source_id>/` 至少包含不可变 `original.pdf`、`source.json` 与 `manifest.json`；Source manifest 列出除自身外的 ingest 文件、实际 byte length、SHA-256 与 media type/Schema identity。`active_source.json` 只在完整 Source bundle 提交后原子替换，并同时绑定 Work ID、Source ID、完整 Source SHA-256 与 manifest SHA-256。

这些 Gezhi JSON 都使用 UTF-8、无 BOM、canonical key order/compact separators 和恰好一个末尾 LF，并分别通过 `gezhi.literature_work.v1`、`gezhi.literature_work_identity.v1`、`gezhi.literature_work_identity_current.v1`、`gezhi.literature_source.v1`、`gezhi.literature_source_manifest.v1` 与 `gezhi.literature_active_source.v1` 识别。Reader 必须把 canonical bytes、ID/hash 绑定、原件 bytes、manifest inventory 与 Active Source 交叉关系作为一个整体复验；目录名、mtime、stdout 或 SQLite row 都不能替代这些证据。改变这些权威 Schema 或路径需要新 generation 和既有资产迁移；OCR、Canonical、Semantic run 的内部文件名仍由后续合同拥有，本决策不提前冻结。

新 Work 与 Source 都先在同一 Literature volume 的 `.staging` 完整形成并 readback；Source directory 与 Work directory 使用 non-replacing rename 发布，current pointer 使用同目录临时文件原子替换。每次新 Work attempt 先在唯一 `intake-*` 私有目录中形成完整 descriptor、Source、identity 与 Active Source；早期 partial attempt 永不成为 authority，也不占用固定 Work staging 名。只有完整且自证的 attempt 才先以 non-replacing rename进入固定 `.staging/<work_id>`，从而让 crash 后 writer只补最终 Work rename；partial attempt由后续 invocation确定性忽略并以同一 reservation Work ID重建，而不是修补成 success。Work 尚未解析时使用绑定 Data Root physical identity 的 root-level writer ownership；解析后先写入 `gezhi.literature_intake_reservation.v1` 私有 reservation，再释放 root scope并取得同一 physical root 与 Work ID 绑定的 Work ownership。Reservation 不是正式资产，但让并发或 crash 后的 writer 对相同 Source/强别名复用同一 Work ID；完整 authority 发布后尽力撤销，遗留的有效 reservation 继续作为保守身份事实，普通 reader 始终忽略它。同一线程最多持有一个 Work writer ownership；跨 Work 或跨 root 的第二个 Work lease是生命周期错误，不得伪装成外部争用。

`catalog.sqlite3` 只是一份可丢弃投影。每次成功 add 都从所有有效 Work、identity、Source manifest/original 与 Active Source authority 构造新的完整临时数据库，通过 SQLite integrity check 后原子替换 catalog；Work 的 aliases 与 `identity_sha256` 必须从同一次已验证 identity revision snapshot 一起冻结，投影期间不得重读 pointer 后拼接两个 revision。损坏、缺失或陈旧 catalog 不参与 Work/Source 解析。投影发布另由绑定同一 root physical identity 的 `Global\\` catalog-projection mutex 串行化，不能用它替代或延长 identity-intake/Work 身份决议；零等待争用按既有 `catalog_projection_failed` 失败并由相同输入重试。若 authority 已提交而投影失败，不回滚文件事实，相同输入重试会复用 Source 并重新生成投影。

V1 的并发与恢复威胁边界是服从同一 Windows `Global\\` named mutex 的 Gezhi writer，以及 crash 后重新观察到的本地文件系统状态。实现保持 Data Root anchor、在 Source/Work rename 与每一个 identity/Active Source/catalog replace 紧邻前重验 root identity，并对正式输入和资产使用 no-follow handle readback；checkpoint 后漂移统一停止为 `data_root_integrity_lost`，不得被重分类成 commit 或 projection failure。正式 Work 缺少 `identity/current.json` 时是不完整 authority，绝不等价于“空别名”；V1 没有足够的冻结恢复证据时不从孤立 revision 猜测 current，而是要求身份复核。实现不声称抵御不服从 mutex 的高权限恶意本机进程，也不提供 power-loss durability。引入独立 File 实体、把 SQLite 作为权威、按路径/文件名生成 Source ID、覆盖既有 Source、或在 duplicate 时复制第二份权威原件，都与本决策不兼容。
