# 用一个不可变 argv snapshot 驱动 preflight 与 Typer

每次受支持的 one-shot `gezhi` invocation 都必须在进入无参数 `gezhi.bootstrap:main` 后，恰好一次读取 CPython 已物化的 `sys.argv`，并立即形成 invocation-local `tuple[str, ...]`：`argv_snapshot = tuple(sys.argv)`。这个 tuple 是本次 project-owned bootstrap、`RawArgvPreflightV1` 与 Typer 参数解析的唯一 argv authority；项目后续不得重新读取、替换或修改 `sys.argv`，也不得改读 `sys.orig_argv`、`GetCommandLineW` 或其他 Windows raw-command-line source。Snapshot 逐项保留 CPython-decoded Python `str` 的值、Unicode 内容与顺序，不做 trim、normalization、case folding、re-tokenization、path interpretation、environment lookup 或其他转换。

`RawArgvPreflightV1` 接收完整 `argv_snapshot`，包括 index `0`；[ADR 0114](./0114-exclude-argv-zero-from-raw-argv-resource-measurement.md) 已冻结全部资源计量只投影 index `1..n`，index `0` 不参与 argument-count、per-argument、aggregate 或独立 resource ceiling。只有 preflight PASS 后，项目才按 [ADR 0111](./0111-lazy-import-the-cli-framework-and-command-graph-after-argv-preflight.md) lazy-import 并构造 Typer command graph；最终 Typer 0.27.0 command invocation 必须显式接收 `args=argv_snapshot[1:]`、`prog_name="gezhi"` 与 `windows_expand_args=False`。Help、version、known/unknown command 及空参数序列都使用同一规则；禁止把 `args=None` 当作空序列，也禁止让 Typer/Click 自动探测 program name。

Typer 0.27.0 shell completion 会在 normal parser 之前从 `_GEZHI_COMPLETE`、`_TYPER_COMPLETE_ARGS` 与 `_TYPER_COMPLETE_WORD_TO_COMPLETE` 等环境输入重建另一组 arguments，因此它与唯一 snapshot authority 不兼容，Gezhi Windows V1 不提供 shell completion。CLI app 必须使用 `add_completion=False`，不得注册 `--install-completion` 或 `--show-completion`；项目 root `TyperGroup` 的 `_main_shell_completion(...)` 必须是 project-owned no-op，不得调用 Typer completion handler、读取上述 completion environment input、重切词或提前退出。上述两个字面 option 因而按普通 unknown-option grammar failure 处理；外部已有 completion script 设置环境变量并调用 `gezhi` 时，这些变量没有特殊语义，进程仍只处理本次 CPython snapshot。后续若要支持 completion，必须另行冻结其独立输入、资源门禁、输出与安全边界，不能静默恢复 Typer 默认行为。

这里的 feed-through 只要求 Typer 接收的 argument token 与 snapshot index `1..n` 在值、Unicode 内容、数量及顺序上逐项完全相同，不要求 tuple slice、Typer 内部派生的 mutable list 或单个 `str` object 具有 identity 相等。Typer 可以为 parser 内部状态复制容器，但项目不得在 preflight 与 parser 之间删除、插入、合并、拆分、重排或改写 token。固定 `prog_name="gezhi"` 只为两个 launcher 提供同一个产品显示名并阻止 Click 重读 `sys.argv[0]`；它不覆盖、规范化或替代 snapshot index `0`，两个 launcher 的真实 `argv[0]` 仍可不同。

`windows_expand_args=False` 是显式、可审计且升级时必须保持的边界，即使当前 Typer 在收到显式 `args` 时已经不会进入 Windows expansion branch。因而 Typer/Click 不得把 `%NAME%` 或 `$NAME` 形式的 environment reference、`~`、`*`、`?`、character class 或 recursive glob 展开为环境值、用户目录或文件系统匹配；这些字符在 parser boundary 仍是 literal token 内容，也不存在 expansion 后的第二份 argv 或第二次 resource preflight。Shell、launcher 或 CPython 在 `bootstrap.main` 之前已经产生的 token 形状位于项目控制之外，本 ADR 不声称恢复原始 quoting 或阻止外部调用者预先展开参数。

Snapshot 只在本 invocation 内存中作为启动权威输入，生命周期覆盖 preflight 与 CLI processing，随后自然释放；preflight/bootstrap 不得把完整 snapshot 或原始 token 内容持久化、记录、散列、裁剪、编码或回显。这不禁止 parser/handled adapter 在进入各自已冻结合同后，按领域规则验证、规范化并持久化合法 Question、路径或其他业务值。`sys.argv` shape/type 异常、snapshot allocation/`MemoryError` 或 feed-through invariant failure 仍是尚未冻结 presentation/exit 的 bootstrap/internal failure，不得冒充 resource violation、parser argument failure 或 Knowledge outcome。

本 ADR 不冻结 Typer `standalone_mode`、其他 bootstrap/internal 异常 presentation 或私有 app-factory/module layout；argv0 的计量排除已由 ADR 0114 独立冻结，argument-count/per-argument/aggregate 的具体数值、`len(str)` 单位、精确 aggregate 与 inclusive 边界已由 [ADR 0115](./0115-cap-raw-argv-at-128-arguments-8192-elements-each-and-16384-total.md) 独立冻结，resource violation 的无 payload verdict、dimension non-disclosure、固定 stderr/empty stdout 与 exit `2` 已由 [ADR 0116](./0116-return-2-with-one-fixed-stderr-line-for-raw-argv-resource-violation.md) 独立冻结并授权 production rejection。Malformed snapshot、snapshot allocation/`MemoryError` 与 feed-through invariant failure 仍保持前段的独立 internal boundary。它也不增加依赖、配置、CLI option、diagnostic code、持久资产或模型调用。

Contract tests 必须覆盖两个真实 launcher，并证明每次 invocation 只建立一个 snapshot；preflight 观察完整 tuple，PASS 后 parser 观察其 exact index `1..n` feed-through；snapshot 后毒化或替换 `sys.argv` 不影响后续路径；真实匹配文件存在时 wildcard、`~` 与 environment reference 仍按 literal token 交付；Typer expansion helper 与 program-name detector 均未被调用；help/version、known/unknown command 与 `args=()` 都遵守相同边界。另须证明 root graph 不拥有 `--install-completion`/`--show-completion`，设置任意 Typer completion environment input 也不会调用 completion handler、读取 completion words 或改变 snapshot/parser feed-through。测试应以值与顺序为断言，不错误要求 Typer 内部容器 identity，并把遗漏显式 `args`、`prog_name`、`windows_expand_args=False`、`add_completion=False` 或 root completion no-op 视为回归。

该选择以一次 tuple allocation、三个显式 Typer 参数、关闭 shell completion 与跨 preflight/parser 的 feed-through 测试，换取一个可审计的 argv trust boundary：资源门禁与 grammar parser 对同一批 CPython-decoded token 作不同层次的判断，且不会因 Windows convenience expansion、第二次进程参数读取、completion environment input 或 launcher 差异而发生 input drift。
