# 在 bridge 激活前清除当前 CLI 进程继承的 Ctrl+C ignore

只有 ADR 0103 console capability classifier 已选择 `interactive_candidate`，且 [ADR 0105](./0105-use-the-no-source-profile-when-the-current-process-is-being-debugged.md) 已以唯一一次 `IsDebuggerPresent` 返回 zero 证明 `debugger_absent` 后，才执行本决策。Parser 已完成 grammar、recognized raw values 已保留且尚未启动任何领域 gate 时，唯一主编排线程先以稳定 `HandlerRoutine` pointer 完成 registration，使 bridge 进入 `ARMED_PASS_THROUGH`；随后对当前 Gezhi CLI 进程恰好调用一次 `SetConsoleCtrlHandler(NULL, FALSE)`，只有返回 nonzero 并完成 state proof 后才允许原子进入 `ACCEPTING`。该调用用于把不可查询的 inherited Ctrl+C-ignore 属性规范化为 normal processing，不是 callback registration、cancellation observation、handler removal 或 prior-state restoration。

Registration 前或 ignore normalization 前的 Ctrl+C 服从当时实际进程状态；若 inherited ignore 仍启用，它可能被忽略。Normalization 成功后，实际投递给 Gezhi `HandlerRoutine` 的 callback 若在 activation 线性化前取得同一 native admission gate，则固定按 `ARMED_PASS_THROUGH` 返回 `FALSE`，不得写 ADR 0098 latch，并可继续到后续/default handler；若 activation 先取得该 gate，callback 才按 `ACCEPTING` 参加 ADR 0101 admission。不得依据按键时间、OS event 生成时间、handler thread 创建时间或事后 timestamp 追溯改判。`SetConsoleCtrlHandler(NULL, FALSE)` 失败、返回状态无法证明、调用次数不唯一或 activation 是否发生不确定时，不启动领域工作、不重试或猜测，也不形成正常 envelope/normal-return exit。

Gezhi v1 CLI 是一个进程只执行一个命令的 standalone owner；normalization 成功后不保存、推测或恢复未知的 inherited-ignore 值，也绝不调用 `SetConsoleCtrlHandler(NULL, TRUE)`。ADR 0100 release 仍只使用注册时同一 function pointer 执行 `SetConsoleCtrlHandler(pointer, FALSE)`，不会以 NULL call 冒充 matching removal。进程退出自然销毁该 process-local 属性；未来若支持嵌入其他宿主或同进程多 invocation，必须建立新合同，不能复用本决策。

该属性不改变已经存在的其他进程，但会成为此后新子进程的继承基线。[ADR 0106](./0106-run-command-owned-children-without-a-console.md) 已冻结每次项目直接启动的 orchestrator-owned Codex attempt root 都必须在 launch commitment 前证明 no-console/no-process-group、三路 stdio、handle allowlist 与 Job handoff；只有该 launch plan 完整成立后才可执行 `CreateProcessW`，不得回退为继承当前 console 的普通启动。本 ADR 不调用 `AllocConsole`、`AttachConsole`、`FreeConsole`、`GenerateConsoleCtrlEvent` 或 `SetConsoleMode`，不修改共享 `ENABLE_PROCESSED_INPUT`，也不判定 attached console、stdin redirection、ConPTY/Terminal、debugger 或无 console profile；ADR 0103、ADR 0104 与 ADR 0105 分别闭合 capability classifier、capability-absent no-source profile 与 debugger-present no-source selection。

后续 [ADR 0103](./0103-require-a-read-only-conin-processed-input-capability-gate.md) 已用只读 `CONIN$`/`GetConsoleMode` 闭合 attached console、stdin redirection、ConPTY/Terminal 与 `ENABLE_PROCESSED_INPUT` 候选门禁；[ADR 0104](./0104-continue-with-a-no-source-cancellation-profile-when-capability-is-absent.md) 已冻结 `capability_absent` 时不执行本 normalization 的 no-source lifecycle，[ADR 0105](./0105-use-the-no-source-profile-when-the-current-process-is-being-debugged.md) 已冻结 debugger present 时同样不执行本 normalization，[ADR 0106](./0106-run-command-owned-children-without-a-console.md) 已冻结 orchestrator-owned Codex attempt-root isolation。
