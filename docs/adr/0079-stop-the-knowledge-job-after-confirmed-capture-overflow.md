# 确认 Knowledge capture overflow 后停止整个 Job 并安全排空

Knowledge v1 为每个 attempt capture 维护进程内、逐通道且只能从 `false` 变为 `true` 的 overflow latch，不把它增加为配置或 manifest 字段。`events.jsonl` collector 按原始到达顺序处理任意 binary chunk：先把仍可容纳的 `min(chunk_length, cap - retained_length)` bytes 写入 prefix sink；只有当前 chunk 还剩至少一个 byte，或 sink 已恰好达到 cap 后又读到下一次非空 chunk，才以实际第 `cap + 1` 个 byte 作为 witness 锁存 events overflow。恰好 cap 后 EOF 合法，不得仅因 sink 已满推断 overflow。锁存后该通道仍持续读取 pipe 到 EOF，但只丢弃 tail，不解析、不哈希且不写入正式资产；由 final overflow 触发 Job 停止时，尚未 overflow 的 events 通道仍继续保留机械 drain 实际取得的 bytes，直到自身 cap，不能全局丢弃“stop request 之后”的 stdout。

`final_message.txt` writer-private spool 必须为该 attempt 的 fresh、唯一私有路径，launch 前不得已有任何 entry，也不得跨 attempt 复用。活跃期监测是 best-effort：固定轮询 cadence 不属于合同，pathname 的 metadata length 只能作为唤醒提示，不能单独证明 overflow。可靠的活跃期 witness 必须来自安全打开的同一 file generation/identity——实际读取 offset `cap` 的 byte——并把该 generation 与不可逆 latch 关联；文件尚未创建、sharing violation、暂时打不开或一次轮询漏检既不证明未 overflow，也不单独构成 collector failure，`turn.completed`、root exit 或 exit code 也不证明 spool 已形成、完整或关闭。整个 Job 已确认静止且 writer source 已关闭后必须对最终 source 做权威复验：未提前 latch 而最终长度大于 cap 时此刻锁存并形成该 generation 的 exact prefix，Job 已空则不再请求终止；提前 latch 后若最终 generation 仍独立证明 overflow，则从它的 offset 0 形成 prefix。提前 latch 后 source 缺失、不可读、缩至不大于 cap，或 replacement 后的新 generation 未独立证明 overflow 时，不得清除 latch、降级为空捕获或拼接 generation，只能留下 staging；replacement 后的新 generation 自身也独立 overflow 时可以按它重新证明并形成 exact prefix。

每个 Codex attempt 都必须先满足 [ADR 0106](./0106-run-command-owned-children-without-a-console.md)：项目 resolver 已证明的 native Codex CLI root 以 `CREATE_SUSPENDED | CREATE_NO_WINDOW | EXTENDED_STARTUPINFO_PRESENT | CREATE_UNICODE_ENVIRONMENT` 和三项 stdio handle allowlist 直接创建，加入该 attempt 独占、non-breakaway、`KILL_ON_JOB_CLOSE` 的 Windows Job Object，父进程关闭 child-side duplicate，且 `ResumeThread` 精确返回 previous suspend count `1` 后，才承认 provider 工作已经开始；Job assignment/resume 失败不得无 Job 或用普通 launch 降级。Events、final、timeout 与 interrupt 只向唯一编排器提交事实和 stop request，collector 不直接竞争调用终止 API；第一次确认任一 capture overflow 后，如果整个 Job 尚未被证明为空，编排器请求终止整个 Job，若已证明 root signaled 且 Job active-process count 为零则不发无意义请求。Root 退出不等于 Job 为空，终止 API 返回成功也不等于已经静止；检查、自然退出与终止调用的竞态一律以最终 root signaled 加 Job active-process count 为零收敛，调用失败但随后证明 Job 已空不单独决定终态。

Stop request 后，Job teardown 与 mechanical drain 并行：父进程停止写入并关闭专用 stdin-write，创建返回后遗留的 child-side duplicates 必须早已关闭；stdout collector 从运行期持续读到 EOF 并按通道规则保存或丢弃，stderr 已由 ADR 0106 唯一预先导向 `NUL`，不存在 stderr pipe、持久化或事后语义解析。这些动作不是继续等待/接受 provider 语义输出，不允许 parsing、validation、retry 或新的模型执行。只有 Job 已空、stdout pipe 已到 EOF、stdin writer 与 stdout collector 均已 join、final 已完成关闭后权威复验、两个正式 sink 已安全关闭/读取/哈希并成对安装、spool/tail/私有临时文件均已撤销，而且全部 monitor 已 join、不会再产生 latch，才能到达 capture-finalization boundary；无法证明任一条件时只能留下 staging。ADR 0080 冻结 boundary 后的分类：两个 latch 做 OR，任一为 true 就固定最高优先级且不可重试的 `process_error`。分类后按 ADR 0081 从已复验正式 events 长度冻结 usage，再形成 item 并映射 `failed: codex_process_failed`、`stage=synthesis`；events latch 为 true 却无法形成 exact-cap 正式资产，或 usage 无法唯一复验时仍只能留下 staging。终止 API 调用结果不是分类点；最终 Job 与全部安全条件收敛就按 overflow 映射，否则只留 staging。`TerminateJobObject` 内部退出 DWORD 与外部诊断继续后续冻结；本决策不增加第三方依赖、稳定轮询间隔、配置、marker、sidecar 或 manifest/attempt 字段，也不改变 ADR 0076 对 spool 瞬时物理峰值不作硬上限承诺的范围。
